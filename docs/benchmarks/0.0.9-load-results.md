# 0.0.9 load and migration evidence

All numbers from throwaway databases (never prod): local PostgreSQL 18.7 for the
engine benchmarks, GitHub Actions PostgreSQL 16 + 18 for the migration-verify legs.
Scripts are committed under `tests/load/` and re-runnable.

## Track 5 - wildcard index templates (P1-3)

Script: `tests/load/track5-template-index-bench.ts`
Dataset: 84,000 documents - one chat with 60,000 messages plus 60 chats of 400
(61 concrete paths under the template `chats/{*}/messages`).

| Step | Result |
| :-- | :-- |
| Unindexed `orderBy` on the 60k subcollection | `FAILED_PRECONDITION` (>50k unindexed cap); `suggestedIndex.collectionPath` = `chats/*/messages` (canonical template, concrete path kept as `exampleCollectionPath`) |
| Unindexed `orderBy` on a 400-doc chat | served (behavior unchanged under the cap) |
| Template backfill (84,000 entries, segment-wise match, tuple pagination) | `ready` in ~13.5s |
| Indexed `orderBy`, 60k-doc chat (40 runs) | p50 2.1ms, p95 5.3ms, `indexUsed: composite:<template id>` |
| Indexed `orderBy`, second chat under the same template (40 runs) | p50 2.8ms, p95 10.0ms, same template index |
| Write after backfill into a chat the backfill never saw | entry lands in the template index; query served from it |

The benchmark caught the release-blocking schema bug fixed in this track: with the
old `document_index_entries` primary key `(index_id, sort_key, document_id)`,
`ON CONFLICT DO NOTHING` silently dropped entries whose `(sort_key, document_id)`
repeated across concrete paths - backfill reported `ready` with 60,000 of 84,000
entries. Data migration 0017 re-keys the table on
`(index_id, collection_path, sort_key, document_id)`; re-run: 84,000/84,000 across
61 concrete paths.

## Migration 0017 rehearsal (populated throwaway, 60,000 entries)

| Operation | Time | Lock |
| :-- | :-- | :-- |
| 0017 up (drop old PK, add new PK) | 121ms total (1ms + 120ms) | ACCESS EXCLUSIVE on `document_index_entries` only |
| 0017 down, no template indexes present | 68ms | same |
| 0017 down with cross-path duplicates present | fails (unique violation) - drop template indexes first; entries cascade on delete | - |

On an empty prod data DB the lock window is instant.
