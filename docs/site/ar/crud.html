CRUD ومسارات المستندات#

كل مورد في مستوى البيانات يُعنون بمسار قياسي UTF-8 مفصول بـ /. تتناوب المسارات بين مقاطع المجموعات ومقاطع معرّفات المستندات.

السيناريو#

أنت تنمذج عميلًا وطلباته: مستند واحد عند users/u_123، ومجموعة فرعية للطلبات عند users/u_123/orders/ord_456. تنشئ المستخدم، وتعدّل حقلًا بطابع زمني من الخادم، وتحمي التعديل بشرط إصدار (version precondition)، ثم تقرأ المستند مع بياناته الوصفية.

قواعد المسار#

النوعالمقاطعأمثلة
مستندزوجي، 2–10users/u_123, users/u_123/orders/ord_456
مجموعةفردي، 1–9users, users/u_123/orders

يسمح مسار بعمق 10 بخمس مجموعات متداخلة. بالنسبة إلى users/u_123/orders/ord_456:

العنصرالقيمة
pathusers/u_123/orders/ord_456
collectionPathusers/u_123/orders
collectionGrouporders
documentIdord_456
pathDepth4

قيود المقاطع#

  • بحد أقصى 1,500 بايت لكل مقطع (UTF-8).
  • لا / ولا بايت NUL ولا أحرف تحكم ASCII (0x00–0x1F).
  • تُرفض . و...
  • المقاطع المطابقة للنمط ^__.*__$ (مثل __name__) محجوزة لبيانات محرك الأعمال ويُرفض استخدامها في مسارات المستخدمين.
WARNING

تجاوز حد العمق يُثير INVALID_DOCUMENT_PATH (400). المقاطع الطويلة جدًا أو المحجوزة تُنتج الرمز نفسه.

مراجع المستندات والمجموعات#

TS
import { createClient } from "@vellumdb/sdk-js";

const db = createClient({ projectId: "<YOUR_PROJECT_ID>", apiKey: "<YOUR_API_KEY>" });

// مرجع مستند (عدد زوجي من المقاطع).
const user = db.doc("users/u_123");

// مرجع مجموعة (عدد فردي من المقاطع)، ثم مستند بداخلها.
const orders = db.collection("users/u_123/orders");
const order = orders.doc("ord_456");

// مجموعة فرعية متداخلة من مرجع مستند موجود.
const events = user.collection("events"); // users/u_123/events

المراجع عبارة عن أدوات بناء غير قابلة للتعديل؛ استدعاء طريقة على مرجع يُرجع قيمة جديدة بالحالة المحدّثة عند الاقتضاء.

create وset وupdate وdelete#

TS
// create — يفشل بـ ALREADY_EXISTS إذا كان المسار مشغولًا.
await user.create({ name: "Ada", role: "admin" });

// set — يستبدل افتراضيًا، أو يدمج بعمق مع { merge: true }.
await user.set({ name: "Ada Lovelace" }, { merge: true });

// update — يعدّل الحقول المقدّمة فقط؛ ويدعم تحويلات الحقول.
await user.update({ lastSeenAt: fieldOp.serverTimestamp() });

// delete — حذف ناعم (علامة حذف + حدث في صندوق البريد).
await user.delete();

يُرجع create وset المستند المخزّن (المسار، ومسار المجموعة، ومعرّف المستند، والبيانات، وversion، وcreatedAt، وupdatedAt). أما update فيطبّق المفاتيح المقدّمة فقط، ويترك المفاتيح الغائبة دون تغيير.

TS
// القراءة تُرجع المستند مع بياناته الوصفية التي يديرها الخادم.
const snap = await user.get();
console.log(snap.path, snap.version, snap.exists, snap.data());

التحكم المتفائل في التزامن بـ ifVersion#

لكل مستند version تتزايد رتيبيًا. مرّر الإصدار المتوقع كشرط مسبق لرفض الكتابة إذا غيّر كاتب آخر المستند أولًا:

TS
const snap = await user.get();
await user.update({ status: "approved" }, { ifVersion: snap.version });
// إذا رفع كاتب آخر الإصدار، تُثير هذه العملية FAILED_PRECONDITION (412).

يقبل كل من set وdelete خيار ifVersion نفسه. يُرجع فشل الشرط المسبق FAILED_PRECONDITION مع expectedVersion وactualVersion في تفاصيل الخطأ. للذرية عبر مستندات متعددة مع شروط مسبقة، استخدم المعاملات.

أساسيات تنسيق الأسلاك الموسوم#

تُخزَّن أنواع JSON الأصلية (null, boolean, string, number المنتهي، array) مباشرةً حتى تتمكن فهارس jsonb_path_ops في PostgreSQL من استخدامها دون حمل إضافي. أما الأنواع الموسّعة فتستخدم المفتاحين المحجوزين $t (الوسم) و$v (القيمة):

النوع المنطقيالتمثيل
int64{ "$t": "int", "$v": "-9007199254740993" }
timestamp{ "$t": "ts", "$v": "2026-11-15T14:30:00.123Z", "$ms": 1794753000123 }
reference{ "$t": "ref", "$v": "users/u_123" }
bytes{ "$t": "bytes", "$v": "SGVsbG8=" } (Base64)
geopoint{ "$t": "geo", "$v": { "lat": 30.0444, "lng": 31.2357 } }
خريطة مستخدم تحتوي $t{ "$t": "map", "$v": { ... } } (هروب تلقائي دون فقدان)
  • يجب أن تكون الأرقام منتهية؛ يُرفض NaN وInfinity.
  • الحد الأقصى لتداخل الكائنات/Mصفوفات هو 20 مستوى (MAX_NESTING_EXCEEDED).
  • الحد الأقصى لطول اسم الحقل 256 حرفًا، ولا يمكن أن يحتوي على أحرف تحكم (INVALID_FIELD_NAME).
  • لا يتجاوز المستند المتسلسل 1 MiB (DOCUMENT_TOO_LARGE).
TIP

يجب أن تكون المراجع ($t: "ref") مسارات قياسية صالحة داخل المشروع والبيئة نفسيهما. هي سلاسل مسارات عادية على مستوى الأسلاك — لا يجلب لك VELLUM المستند الهدف.

الأخطاء الشائعة#

  • الخلط بين مسار المستند ومسار المجموعة. مسار المستند عدد مقاطعه زوجي؛ ومسار المجموعة فردي.
  • استخدام مقطع محجوز. الأسماء مثل __name__ هي بيانات وصفية للمحرك ويُرفض استخدامها في مسارات المستخدمين.
  • توقّع أن create متكرر النتيجة. يفشل بـ ALREADY_EXISTS؛ استخدم set عند الرغبة بالاستبدال.
  • افتراض أن delete يحذف الصف فورًا. إنه حذف ناعم (علامة حذف)، وتتولى مهمة التنظيف حسب فترة الاحتفاظ.

مثال موثّق#

المجموعة / البروتوكول
DART
import 'dart:io';
// Executed against the live PostgreSQL API by scripts/run-dart-examples.mjs.
//
// Document CRUD & optimistic concurrency — manage a versioned user profile.
// What you'll build: a profile created, merged, replaced, conditionally patched
// and deleted, plus a rejected stale write.
// Real-world scenario: a settings screen uses ifVersion so an old tab cannot
// silently overwrite newer profile data.
import 'package:vellum_flutter/vellum_flutter.dart';

Future<void> main() async {
  final endpoint = Platform.environment['VELLUM_API_BASE'] ??
      const String.fromEnvironment('VELLUM_API_BASE',
          defaultValue: 'http://127.0.0.1:8080');
  final projectId = Platform.environment['VELLUM_PROJECT_ID'] ??
      const String.fromEnvironment('VELLUM_PROJECT_ID');
  final apiKey = Platform.environment['VELLUM_API_KEY'] ??
      const String.fromEnvironment('VELLUM_API_KEY');

  final client =
      VellumClient(endpoint: endpoint, projectId: projectId, apiKey: apiKey);
  final prefix = 'ex_flutter_crud_${DateTime.now().microsecondsSinceEpoch}';
  final ref = client.collection(prefix).doc('user-profile');

  try {
    print('=== Document CRUD & Optimistic Concurrency (Flutter) ===');

    // `create` has no dedicated helper on DocumentReference; use request().
    await client.request('POST', '/documents/${ref.path}', body: {
      'data': {
        'displayName': 'Ada Lovelace',
        'email': 'ada@example.com',
        'status': 'active',
        'loginCount': 0,
        'note': 'imported',
      },
    });
    final first = await ref.get();
    print('create profile: version=${first.version}');

    // Partial merge: verifying the email must not drop the other fields.
    await ref.set({'status': 'verified'}, merge: true);
    final merged = await ref.get();
    print(
        'set(merge): version=${merged.version} note=${merged.data()?['note']}');

    // Full replacement.
    await ref.set({'displayName': 'Ada L.'}, merge: false);
    final replaced = await ref.get();
    print(
        'set(replace): version=${replaced.version} keys=${replaced.data()?.keys.toList()}');

    // Guarded patch.
    await ref.update({'loginCount': 7}, ifVersion: 3);
    final patched = await ref.get();
    print(
        'update(ifVersion=3): version=${patched.version} loginCount=${patched.data()?['loginCount']}');

    try {
      await ref.update({'loginCount': 99}, ifVersion: 3);
    } on VellumException catch (e) {
      print('stale tab: code=${e.code} status=${e.statusCode}');
    }

    await ref.delete(ifVersion: 4);
    print('delete(ifVersion=4): true');
  } finally {
    try {
      await ref.delete();
    } catch (_) {
      // Best effort cleanup.
    }
    client.dispose();
  }
}

/**
 * Document CRUD & optimistic concurrency — manage a user profile with
 * versioned writes.
 *
 * What you'll build: a single user profile that is created, merged, replaced,
 * conditionally patched and finally deleted.
 * Real-world scenario: a settings screen does a partial "verify email" merge,
 * a full profile replacement, and a guarded login-count bump. A second,
 * stale write from an old tab is rejected with FAILED_PRECONDITION instead of
 * silently overwriting newer data.
 */
import { harness, check } from "./_harness.js";

const h = await harness("crud");
const ref = h.sdk.collection(h.prefix).doc("user-profile");

function errorCode(error: unknown): string {
  return (error as { code?: string }).code ?? "UNKNOWN";
}

try {
  h.log("=== Document CRUD & Optimistic Concurrency ===");

  await ref.create({
    displayName: "Ada Lovelace",
    email: "ada@example.com",
    status: "active",
    loginCount: 0,
    note: "imported",
  });
  const first = await ref.get();
  check(first.version === 1, "create starts at version 1");
  h.log({ operation: "create profile", version: first.version, data: first.data() });

  // Partial update: verifying the email must not drop the other fields.
  await ref.set({ status: "verified" }, { merge: true });
  const merged = await ref.get();
  check(merged.version === 2 && (merged.data() as { note: string }).note === "imported", "merge preserves other fields");
  h.log({ operation: "set(merge) verify status", version: merged.version, data: merged.data() });

  // Full replacement: the client intentionally sends only the final shape.
  await ref.set({ displayName: "Ada L." }, { merge: false });
  const replaced = await ref.get();
  check(replaced.version === 3 && Object.keys(replaced.data()).length === 1, "set replaces the whole document");
  h.log({ operation: "set(replace) minimal profile", version: replaced.version, data: replaced.data() });

  // Guarded patch: only apply the login bump if nobody else changed the doc.
  await ref.update({ loginCount: 7 }, { ifVersion: 3 });
  const patched = await ref.get();
  check(patched.version === 4 && (patched.data() as { loginCount: number }).loginCount === 7, "conditional update applied");
  h.log({ operation: "update(ifVersion=3) loginCount", version: patched.version, loginCount: (patched.data() as { loginCount: number }).loginCount });

  try {
    await ref.update({ loginCount: 99 }, { ifVersion: 3 });
    throw new Error("stale update should have been rejected");
  } catch (error: unknown) {
    check(errorCode(error) === "FAILED_PRECONDITION", "stale ifVersion returns FAILED_PRECONDITION");
    h.log({ operation: "update(ifVersion=3) from stale tab", code: errorCode(error), status: (error as { status?: number }).status });
  }

  await ref.delete({ ifVersion: 4 });
  const missing = await h.api.data("GET", `/documents/${h.prefix}/user-profile`);
  check(missing.status === 404, "deleted profile is gone");
  h.log({ operation: "delete(ifVersion=4)", status: missing.status, code: (missing.body as { error?: { code?: string } })?.error?.code });
} finally {
  await h.cleanup();
}

/**
 * Document CRUD & optimistic concurrency (REST) — manage a versioned profile.
 *
 * What you'll build: a user profile created with POST, merged with PUT,
 * replaced with PUT, conditionally patched with PATCH and deleted with
 * ifVersion. A second, stale PATCH is rejected with FAILED_PRECONDITION.
 * Real-world scenario: a settings screen avoids lost updates by guarding writes
 * with the version it last read.
 */
import { harness, check } from "./_harness.mjs";

const h = await harness("crud");
const docPath = `${h.prefix}/user-profile`;
const codeOf = (reply) => reply.body?.error?.code ?? "UNKNOWN";

try {
  h.log("=== Document CRUD & Optimistic Concurrency ===");

  const created = await h.api.data("POST", `/documents/${docPath}`, {
    data: {
      displayName: "Ada Lovelace",
      email: "ada@example.com",
      status: "active",
      loginCount: 0,
      note: "imported",
    },
  });
  check(created.status === 201, "create profile");
  const first = await h.api.data("GET", `/documents/${docPath}`);
  check(first.body.version === 1, "create starts at version 1");
  h.log({ operation: "create profile", version: first.body.version, data: first.body.data });

  const merged = await h.api.data("PUT", `/documents/${docPath}`, {
    data: { status: "verified" },
    merge: true,
  });
  check(merged.ok && merged.body.version === 2, "merge advanced the version");
  const afterMerge = await h.api.data("GET", `/documents/${docPath}`);
  check(afterMerge.body.data.note === "imported", "merge preserves other fields");
  h.log({ operation: "set(merge) verify status", version: afterMerge.body.version, data: afterMerge.body.data });

  const replaced = await h.api.data("PUT", `/documents/${docPath}`, {
    data: { displayName: "Ada L." },
    merge: false,
  });
  check(replaced.ok && replaced.body.version === 3, "replace advanced the version");
  const afterReplace = await h.api.data("GET", `/documents/${docPath}`);
  check(Object.keys(afterReplace.body.data).length === 1, "replace dropped all other fields");
  h.log({ operation: "set(replace) minimal profile", version: afterReplace.body.version, data: afterReplace.body.data });

  const patched = await h.api.data("PATCH", `/documents/${docPath}`, {
    data: { loginCount: 7 },
    ifVersion: 3,
  });
  check(patched.ok && patched.body.version === 4, "conditional patch applied");
  h.log({ operation: "update(ifVersion=3) loginCount", version: patched.body.version, loginCount: patched.body.data.loginCount });

  const stale = await h.api.data("PATCH", `/documents/${docPath}`, {
    data: { loginCount: 99 },
    ifVersion: 3,
  });
  check(stale.status === 412 && codeOf(stale) === "FAILED_PRECONDITION", "stale patch rejected");
  h.log({ operation: "update(ifVersion=3) from stale tab", code: codeOf(stale), status: stale.status });

  const removed = await h.api.data("DELETE", `/documents/${docPath}?ifVersion=4`);
  check(removed.ok, "delete applied");
  const missing = await h.api.data("GET", `/documents/${docPath}`);
  check(missing.status === 404, "deleted profile is gone");
  h.log({ operation: "delete(ifVersion=4)", status: missing.status, code: codeOf(missing) });
} finally {
  await h.cleanup();
}
