الترقيم الصفحي#

يُرقّم VELLUM الصفوف بـ مؤشرات معتمة موقّعة — ولا يستخدم OFFSET في SQL مطلقًا. ترقيم الإزاحة (offset) ينزلق عند إدراج مستندات أو حذفها بين الصفحات، ويصير أبطأ كلما كبرت الإزاحة. أما الترقيم بالمفتاح (keyset) فيبدأ من صف الحد بالضبط في الصفحة السابقة.

السيناريو#

أنت تعرض خلاصة تمرير لا نهائية للطلبات مرتبة حسب المبلغ الإجمالي. تجلب 20 في كل مرة، وتحتفظ بـ nextCursor المُعاد، وتطلب الصفحة التالية بـ startAfter حتى لا يتكرر آخر صف من الصفحة السابقة — حتى لو أُدرجت طلبات جديدة أثناء تمرير المستخدم.

TS
const q = db.collection("orders").where("status", "==", "paid").orderBy("total", "desc").limit(20);

let cursor: string | null = null;
do {
  const page = await (cursor ? q.startAfter(cursor) : q).get();
  for (const doc of page.docs) console.log(doc.id, doc.data());
  cursor = page.nextCursor; // null تعني أنه لا توجد نتائج أخرى
} while (cursor);
  • يجعل startAt(cursor) مستند الحد مشمولًا (يظهر مجددًا في الصفحة التالية).
  • يجعل startAfter(cursor) مستند الحد مستبعدًا (الاختيار المعتاد للصفحة التالية).

يكون nextCursor مساويًا null عندما لا يجلب الخادم صفًا إضافيًا بعد الصفحة، لذا تنتهي حلقة while (cursor) بسلاسة.

ما الذي بداخل المؤشر#

المؤشر هو جسم JSON مُرمّز بـ base64url مع توقيع HMAC-SHA256:

الحقلالمعنى
qHashتجزئة SHA-256 لـ (projectId, projectId, collectionPath, where, orderBy).
valsقيم حقول الترتيب من مستند الحد.
docIdمعرّف document_id لمستند الحد.
sortKeyمفتاح فرز مركّب مُرمّز بالنظام الست عشري عندما جاءت الصفحة من فهرس مركّب.
sigHMAC-SHA256(CURSOR_HMAC_SECRET, canonicalBody).

تُقارن التوقيعة بزمن ثابت. وتُتحقق تجزئة شكل الاستعلام في كل استخدام:

  • التلاعب بأي حقل يُبطل التوقيعة → INVALID_CURSOR (400).
  • إعادة استخدام مؤشر مع مرشحات أو ترتيب أو مشروع أو بيئة مختلفة يُبطل qHash → INVALID_CURSOR.
  • مؤشر استعلام مفهرس دون مفتاح الفرز الموقّع لا يمكنه الاستئناف → INVALID_CURSOR.
WARNING

المؤشرات معتمة: لا تفكّ ترميزها أو تعدّلها أو أنشئها بنفسك. عاملها كرموز قصيرة العمر. المؤشر ذو معنى فقط للاستعلام الذي أنتجه بالضبط.

فاصل الحسم الحتمي#

الترقيم بالمفتاح لا يكون حتميًا إلا إذا كان ترتيب الفرز كاملًا. يُلحق VELLUM document_id ASC كفاصل حسم أخير بكل قائمة orderBy، لذا تُعاد المستندات المتطابقة في قيم الترتيب دائمًا بالترتيب نفسه، ويمكن للمؤشر تحديد صف الحد بلا لبس.

TS
// حتى لو اشتركت صفوف كثيرة في createdAt، يجعل document_id ASC الترتيب كاملًا.
const page = await db
  .collection("events")
  .orderBy("createdAt", "desc") // يُلحق document_id ASC تلقائيًا
  .limit(25)
  .get();

بالنسبة للاستعلامات المدعومة بالفهارس المركّبة، يُحدد الحد أيضًا بمفتاح sortKey المُرمّز، مما يسمح بشرط keyset واحد على شجرة B (sort_key > <cursor sort key>) بدلًا من إعادة المسح.

لا يوجد OFFSET#

لا توجد معلمة offset في الواجهة العامة. داخليًا يجلب المحرك limit + 1 صفًا ليقرر وجود صفحة تالية، ثم يبني المؤشر من آخر صف أُعيد. عمليات المسح الاحتياطية غير المفهرسة محددة بسقف أمان ولا تُقتطع من النتائج بصمت؛ أما الاستعلام الذي يتطلب فهرسًا مركّبًا فيفشل صراحةً. راجع الاستعلام والفهارس المركّبة.

إعداد البيئة#

تُفتاح توقيعات المؤشرات بـ CURSOR_HMAC_SECRET. تدوير هذا السر يُبطل جميع المؤشرات القائمة. استخدم قيمة قوية وفريدة في الإنتاج، واحتفظ بها ثابتة عبر كل الحالات التي تخدم النشر.

BASH
CURSOR_HMAC_SECRET="<a-long-random-value>"

الأخطاء الشائعة#

  • استخدام startAt للصفحة التالية. يُعيد صف الحد؛ استخدم startAfter للترقيم الحصري.
  • تعديل المؤشرات أو فك ترميزها. هي موقّعة ومعتمة؛ أي تغيير يُنتج INVALID_CURSOR.
  • إعادة استخدام مؤشر مع استعلام مختلف. تجزئة شكل الاستعلام لن تطابق.
  • تدوير CURSOR_HMAC_SECRET أثناء تصفح العملاء. تصبح كل المؤشرات النشطة باطلة ويجب على العملاء البدء من الصفحة الأولى.

مثال موثّق#

المجموعة / البروتوكول
DART
import 'dart:io';
// Executed against the live PostgreSQL API by scripts/run-dart-examples.mjs.
//
// Cursor pagination — list users two at a time via opaque cursors.
// What you'll build: a paged user directory that follows `nextCursor` into
// `startAfter` until no cursor is returned.
// Real-world scenario: an admin list avoids SQL OFFSET; each page is anchored
// to the last row of the previous page. `vellum_flutter` exposes `startAfter`
// only (no `startAt`).
import 'package:vellum_flutter/vellum_flutter.dart';

Future<void> main() async {
  final endpoint = Platform.environment['VELLUM_API_BASE'] ??
      const String.fromEnvironment('VELLUM_API_BASE',
          defaultValue: 'http://127.0.0.1:8080');
  final projectId = Platform.environment['VELLUM_PROJECT_ID'] ??
      const String.fromEnvironment('VELLUM_PROJECT_ID');
  final apiKey = Platform.environment['VELLUM_API_KEY'] ??
      const String.fromEnvironment('VELLUM_API_KEY');

  final client =
      VellumClient(endpoint: endpoint, projectId: projectId, apiKey: apiKey);
  final prefix =
      'ex_flutter_pagination_${DateTime.now().microsecondsSinceEpoch}';
  final col = client.collection(prefix);

  try {
    print('=== Cursor Pagination (Flutter) ===');
    for (var i = 0; i < 6; i++) {
      await col
          .doc('u$i')
          .set({'seq': i, 'status': 'active', 'name': 'user-$i'});
    }

    final base = col.where('status', '==', 'active').orderBy('seq').limit(2);
    Query<Map<String, dynamic>> query = base;
    final seen = <String>[];
    var pageNumber = 0;

    while (true) {
      final page = await query.get();
      pageNumber++;
      final ids = page.docs.map((d) => d.id).toList();
      seen.addAll(ids);
      final next = page.nextCursor;
      print('page=$pageNumber ids=$ids cursorReturned=${next != null}');
      if (next == null) break;
      query = base.startAfter(next);
      if (pageNumber >= 10) break;
    }
    print(
        'pages=$pageNumber total=${seen.length} unique=${seen.toSet().length}');
  } finally {
    for (var i = 0; i < 6; i++) {
      try {
        await col.doc('u$i').delete();
      } catch (_) {}
    }
    client.dispose();
  }
}

/**
 * Cursor-only pagination — walk a user directory two records at a time.
 *
 * What you'll build: a paged "list users" screen that follows the opaque
 * HMAC cursor returned as nextCursor.
 * Real-world scenario: an admin UI pages through a large, ordered directory.
 * No SQL OFFSET is used or exposed — each page is anchored to the last row of
 * the previous page via startAfter, with document_id as the final tie-breaker.
 */
import { harness, check } from "./_harness.js";

const h = await harness("pagination");
const col = h.prefix;

try {
  h.log("=== Cursor Pagination ===");
  for (let i = 0; i < 6; i += 1) {
    await h.sdk.collection(col).doc(`u${i}`).set({ seq: i, status: "active", name: `user-${i}` });
  }

  const base = h.sdk.collection(col).where("status", "==", "active").orderBy("seq", "asc").limit(2);
  const seen: string[] = [];
  let cursor: string | null = null;
  let pageNumber = 0;

  while (true) {
    const query = cursor ? base.startAfter(cursor) : base;
    const page = await query.get();
    pageNumber += 1;
    const ids = page.docs.map((doc) => doc.id as string);
    seen.push(...ids);
    h.log({ page: pageNumber, ids, cursorReturned: page.nextCursor !== null });
    if (page.nextCursor === null) break;
    cursor = page.nextCursor;
    check(pageNumber < 10, "pagination should terminate");
  }

  check(seen.length === 6, "all six users were visited exactly once");
  check(new Set(seen).size === 6, "no user was returned twice");
  h.log({ pages: pageNumber, total: seen.length, unique: new Set(seen).size, nextCursor: null });
} finally {
  await h.cleanup();
}

/**
 * Cursor pagination (REST) — list users two at a time via opaque cursors.
 *
 * What you'll build: a paged user directory that follows `nextCursor` from the
 * /query response into `startAfter` on the next request.
 * Real-world scenario: a large admin list must avoid SQL OFFSET; each page is
 * anchored to the last row of the previous page and stops when nextCursor is null.
 */
import { harness, check } from "./_harness.mjs";

const h = await harness("pagination");
const col = h.prefix;

try {
  h.log("=== Cursor Pagination ===");
  for (let i = 0; i < 6; i += 1) {
    const res = await h.api.data("POST", `/documents/${col}/u${i}`, {
      data: { seq: i, status: "active", name: `user-${i}` },
    });
    check(res.status === 201, `seed user ${i}`);
  }

  const base = {
    collectionPath: col,
    where: [{ field: "status", op: "==", value: "active" }],
    orderBy: [{ field: "seq", dir: "asc" }],
    limit: 2,
    select: null,
    startAt: null,
    startAfter: null,
  };
  const seen = [];
  let cursor = null;
  let pageNumber = 0;

  while (true) {
    const reply = await h.api.data("POST", "/query", { ...base, startAfter: cursor });
    check(reply.ok, `page ${pageNumber + 1} query succeeded`);
    pageNumber += 1;
    const ids = reply.body.documents.map((d) => d.documentId);
    seen.push(...ids);
    const nextCursor = reply.body.nextCursor ?? null;
    h.log({ page: pageNumber, ids, cursorReturned: nextCursor !== null });
    if (nextCursor === null) break;
    cursor = nextCursor;
    check(pageNumber < 10, "pagination should terminate");
  }

  check(seen.length === 6, "all six users visited exactly once");
  check(new Set(seen).size === 6, "no user returned twice");
  h.log({ pages: pageNumber, total: seen.length, unique: new Set(seen).size, nextCursor: null });
} finally {
  await h.cleanup();
}
