الوقت الفعلي#

يبثّ VELLUM التغييرات عبر WebSocket على /v1/realtime. يستخدم التصميم PostgreSQL كخدمة وحيدة تحمل الحالة: يُوقظ LISTEN/NOTIFY مستطلعًا، ويضمن صندوق بريد دائم عدم فقدان أي تغيير.

السيناريو#

أنت تبني لوحة تحكم مشتركة يراقب فيها عدة مشغّلين قائمة الطلبات نفسها. تشترك في لقطة استعلام، فيظهر كل إنشاء أو تعديل لحظيًا. تحتفظ بأحدث watermarkSeqId، فإذا انقطع الاتصال تعيد الاتصال وتُعيد تشغيل الأحداث التي فاتتك فقط.

TS
// اشتراك في مستند.
const stopUser = db.doc("users/u_123").onSnapshot(
  (snapshot) => {
    for (const change of snapshot.changes) {
      console.log(change.type, change.seqId, change.doc.data());
    }
  },
  (error) => console.error("stream failed", error)
);

// اشتراك في استعلام — snapshot.docs هي مجموعة النتائج المُجمَّعة.
const stopQuery = db
  .collection("users")
  .where("online", "==", true)
  .onSnapshot((snapshot) => {
    console.log(snapshot.docs.map((d) => d.id), snapshot.watermarkSeqId);
  });

// لاحقًا: أوقف الاستماع وأغلق الناقل المشترك عند عدم بقاء اشتراكات.
stopUser();
stopQuery();

البنية#

  1. كل تعديل على مستند يُدرج صفًا في realtime_outbox في نفس معاملة قاعدة البيانات التي تعدّل المستند، برقم seq_id تتزايد رتيبيًا.
  2. يُصدر مُحفّز AFTER INSERT إشعار NOTIFY يحتوي فقط على seqId وprojectId وprojectId — ولا على بيانات المستند (يحدّ PostgreSQL حمولة NOTIFY بنحو 8,000 بايت على أي حال).
  3. عميل PostgreSQL واحد مخصص لـ LISTEN يستقبل الإشعار ويوقظ مستطلع صندوق البريد كاشف الفجوات. وتعمل حلقة استطلاع عادية أيضًا، لذا يستمر الوقت الفعلي حتى عند غياب LISTEN (مثل نقطة نهاية المجمّع (pooler) الخاصة بـ Neon).
  4. يجلب المستطلع صفوف صندوق البريد الكاملة عبر مهايئ التخزين المحدد للمستأجر ثم يوزّعها عبر مركز WebSocket. تُخفَّض التكرارات بين NOTIFY والاستطلاع اللذين يلاحظان الصف نفسه بواسطة seqId، مما يمنح تسليمًا لمرة واحدة عند حد الاشتراك.
NOTE

لا يوجد Redis ولا وسيط خارجي. يجب أن يكون اتصال LISTEN المخصص عنوان PostgreSQL بـ وضع الجلسة؛ فنقطة نهاية -pooler الخاصة بـ Neon تُسقط اشتراكات LISTEN على مستوى الجلسة. اضبط DATA_DATABASE_URL_LISTEN لأفضل زمن استجابة، أو اتركه غير محدد للعمل بوضع الاستطلاع فقط.

الاتصال والاشتراك#

يجمع SDK جميع الاشتراكات عبر ناقل WebSocket واحد. اشترك في مسار مستند واحد أو في استعلام — كما في المثال أعلاه. يُرجع onSnapshot دالة إلغاء الاشتراك. أنواع التغيير هي added وmodified وremoved. بالنسبة لاشتراكات الاستعلامات يحمل snapshot.docs مجموعة النتائج الحالية؛ وبالنسبة لمسارات المستندات يكون فارغًا.

في الباطن يرسل العميل إطار auth (projectId, apiKey, وauthToken اختياري) ثم أطر subscribe مع subId وإما path أو query. تُتحقق قواعد الأمان من get على مسار مستند وlist على استعلام مجموعة، تمامًا كما في قراءات HTTP.

أطر الخادم#

الإطارالمعنى

الاستئناف وعلامات المياه وكشف الفجوات#

يحتفظ صندوق البريد بالأحداث مدة 24 ساعة. عندما يوفر اشتراك resumeSeqId داخل هذه النافذة، يُعيد الخادم تشغيل التعديلات الفائتة بترتيب تسلسلي صارم قبل العودة إلى الأحداث الحية:

  • seq_id هي علامة مياه لكل مستأجر. لا تُسلَّم أبدًا قيمة seqId <= watermark مجددًا.
  • إذا تخطت إيقاظة رقمًا تسلسليًا واحدًا أو أكثر، يسجّل المستطلع فجوة ويجلب الصفوف المفقودة.
  • يُعلّم إطار resume_complete الحد: أُعيد تشغيل count حدثًا، وseqId هو آخر تسلسل سُلِّم، وtruncated: true تعني بلوغ سقف 5,000 حدث. تُصدر الأحداث الحية التي وصلت أثناء إعادة التشغيل لاحقًا بترتيب تسلسلي.
  • إزالة التكرارات لكل اشتراك (seenSeqIds) تُسقط التكرارات التي تُظهرها كل من NOTIFY والاستطلاع.
TS
// احفظ علامة المياه حتى تتمكن إعادة الاتصال من تشغيل الفائت فقط.
const stop = db.collection("orders").onSnapshot((snapshot) => {
  if (snapshot.watermarkSeqId != null) {
    localStorage.setItem("orders:watermark", String(snapshot.watermarkSeqId));
  }
  render(snapshot.docs);
});
TIP

احفظ أحدث watermarkSeqId من لقطاتك إذا كنت تحتاج إمكانية الاستئناف. عند إعادة الاتصال، مرّرها كموضع استئناف ليُعيد الخادم تشغيل ما فاتك فقط. يعيد ناقل SDK الاتصال تلقائيًا بتراجع أُسّي وتشويش (exponential backoff and jitter).

الحدود#

الحدالقيمةالخطأ

مدة الاحتفاظ بصندوق البريد24 ساعةلا يمكن استئناف الأحداث الأقدم

يُفصل المستهلكون البطيئون بدلًا من السماح بنمو الذاكرة بلا حد. أبقِ استدعاءات اللقطة سريعة وفَرِّغ العمل الثقيل إلى مكان آخر.

الأخطاء الشائعة#

  • أداء عمل ثقيل داخل استدعاء اللقطة. المستهلك البطيء قد يتجاوز مخزن 1 MiB الصادر ويُفصل.
  • تجاوز 50 اشتراكًا على اتصال واحد. يرفض الخادم الاشتراكات الجديدة بـ SUBSCRIPTION_LIMIT_EXCEEDED.
  • توقّع الاستئناف بعد 24 ساعة. الأحداث الأقدم ضُغطت ولا يمكن إعادة تشغيلها.
  • استخدام عنوان مجمّع لـ LISTEN. نقطة -pooler في Neon تُسقط LISTEN على مستوى الجلسة؛ استخدم عنوان وضع جلسة أو اقبل وضع الاستطلاع فقط.

مثال موثّق#

المجموعة / البروتوكول
DART
import 'dart:io';
// Executed against the live PostgreSQL API by scripts/run-dart-examples.mjs.
//
// Realtime snapshots — watch a sensor document and a channel query.
// What you'll build: a live ops dashboard that listens via `snapshots()` and
// observes a new reading and a new matching sensor.
// Real-world scenario: the SDK multiplexes subscriptions over one WebSocket
// transport with full-jitter reconnect; cancelling the stream unsubscribes.
import 'package:vellum_flutter/vellum_flutter.dart';

Future<void> main() async {
  final endpoint = Platform.environment['VELLUM_API_BASE'] ??
      const String.fromEnvironment('VELLUM_API_BASE',
          defaultValue: 'http://127.0.0.1:8080');
  final projectId = Platform.environment['VELLUM_PROJECT_ID'] ??
      const String.fromEnvironment('VELLUM_PROJECT_ID');
  final apiKey = Platform.environment['VELLUM_API_KEY'] ??
      const String.fromEnvironment('VELLUM_API_KEY');

  final client =
      VellumClient(endpoint: endpoint, projectId: projectId, apiKey: apiKey);
  final prefix = 'ex_flutter_realtime_${DateTime.now().microsecondsSinceEpoch}';
  final col = client.collection(prefix);
  final ref = col.doc('sensor-1');

  try {
    print('=== Realtime Snapshots (Flutter) ===');
    await ref.set({'reading': 1, 'channel': 'sensors'});

    final docSub = ref.snapshots().listen((snap) {
      print(
          'document change: version=${snap.version} reading=${snap.data()?['reading']}');
    });
    final querySub =
        col.where('channel', '==', 'sensors').snapshots().listen((page) {
      print(
          'query snapshot: count=${page.docs.length} watermark=${page.watermarkSeqId}');
    });

    await Future<void>.delayed(const Duration(seconds: 1));
    await ref.update({'reading': 2});
    await col.doc('sensor-2').set({'reading': 3, 'channel': 'sensors'});
    await Future<void>.delayed(const Duration(seconds: 1));

    final finalDoc = await ref.get();
    print('finalReading=${finalDoc.data()?['reading']}');

    await docSub.cancel();
    await querySub.cancel();
  } finally {
    for (final id in ['sensor-1', 'sensor-2']) {
      try {
        await col.doc(id).delete();
      } catch (_) {}
    }
    client.dispose();
  }
}

/**
 * Realtime snapshots — watch a sensor feed and a matching query.
 *
 * What you'll build: a live ops dashboard that listens to one sensor document
 * and to a channel query, and observes changes without re-polling manually.
 * Real-world scenario: a monitoring screen must reflect a new reading the
 * instant it is written. The document subscription sees value changes; the
 * query subscription sees a new matching sensor appear.
 *
 * If a browser-free Node WebSocket cannot be established, the example degrades
 * to a clearly-labelled REST polling fallback. The mutation is always asserted.
 */
import { harness, check } from "./_harness.js";

const h = await harness("realtime-snapshot");
const col = h.prefix;
const docPath = `${col}/sensor-1`;

interface ReceivedEvent {
  type: string;
  id: string;
  value: unknown;
}

const sleep = (ms: number): Promise<void> => new Promise((resolve) => setTimeout(resolve, ms));

async function waitFor(
  events: ReceivedEvent[],
  predicate: (event: ReceivedEvent) => boolean,
  timeoutMs = 6000
): Promise<ReceivedEvent | null> {
  const deadline = Date.now() + timeoutMs;
  while (Date.now() < deadline) {
    const found = events.find(predicate);
    if (found) return found;
    await sleep(50);
  }
  return null;
}

try {
  h.log("=== Realtime Snapshots ===");
  await h.sdk.collection(col).doc("sensor-1").set({ reading: 1, channel: "sensors" });

  // --- Document subscription -------------------------------------------------
  const docEvents: ReceivedEvent[] = [];
  const unsubscribeDoc = h.sdk.doc(docPath).onSnapshot((snapshot) => {
    for (const change of snapshot.changes) {
      const data = change.doc.data() as Record<string, unknown>;
      docEvents.push({ type: change.type, id: change.doc.id, value: data["reading"] });
    }
  });
  const initial = await waitFor(docEvents, (event) => event.type === "added");

  let mode: string;
  if (initial) {
    mode = "native WebSocket onSnapshot";
    await h.sdk.collection(col).doc("sensor-1").update({ reading: 2 });
    const modified = await waitFor(docEvents, (event) => event.type === "modified" && event.value === 2);
    check(Boolean(modified), "document subscription observed the new reading");
    h.log({
      transport: mode,
      target: "document",
      initialType: initial.type,
      observedTypes: docEvents.map((event) => event.type),
      finalReading: modified?.value,
    });
  } else {
    mode = "REST polling fallback (WebSocket unavailable)";
    await h.sdk.collection(col).doc("sensor-1").update({ reading: 2 });
    let observed = false;
    const deadline = Date.now() + 6000;
    while (Date.now() < deadline) {
      const snap = await h.sdk.collection(col).doc("sensor-1").get();
      if ((snap.data() as { reading: number }).reading === 2) {
        observed = true;
        break;
      }
      await sleep(100);
    }
    check(observed, "REST GET eventually observed the committed reading");
    h.log({ transport: mode, target: "document", initialCallback: false, readingViaRest: 2, mutationAsserted: true });
  }
  unsubscribeDoc();

  // --- Query subscription ----------------------------------------------------
  // The realtime subscribe frame strips unused null members and opaque cursors.
  const channelQuery = h.sdk.collection(col).where("channel", "==", "sensors");

  const queryEvents: ReceivedEvent[] = [];
  const unsubscribeQuery = channelQuery.onSnapshot((snapshot) => {
    for (const change of snapshot.changes) {
      queryEvents.push({ type: change.type, id: change.doc.id, value: (change.doc.data() as { reading?: number }).reading });
    }
  });
  const queryInitial = await waitFor(queryEvents, (event) => event.type === "added");

  if (queryInitial && mode === "native WebSocket onSnapshot") {
    await h.sdk.collection(col).doc("sensor-2").set({ reading: 3, channel: "sensors" });
    const added = await waitFor(queryEvents, (event) => event.type === "added" && event.id === "sensor-2");
    check(Boolean(added), "query subscription observed the new matching sensor");
    h.log({
      transport: mode,
      target: "query",
      initialCount: 1,
      observedTypes: queryEvents.map((event) => event.type),
      addedId: added?.id,
    });
  } else {
    await h.sdk.collection(col).doc("sensor-2").set({ reading: 3, channel: "sensors" });
    let count = 0;
    const deadline = Date.now() + 6000;
    while (Date.now() < deadline) {
      const result = await h.sdk.collection(col).where("channel", "==", "sensors").get();
      count = result.docs.length;
      if (count === 2) break;
      await sleep(100);
    }
    check(count === 2, "REST query eventually returned both matching sensors");
    h.log({ transport: mode, target: "query", initialCallback: false, countViaRest: count, mutationAsserted: true });
  }
  unsubscribeQuery();

  const finalDoc = await h.sdk.collection(col).doc("sensor-1").get();
  check((finalDoc.data() as { reading: number }).reading === 2, "final sensor reading is committed");
  h.log({ finalReading: (finalDoc.data() as { reading: number }).reading });
} finally {
  await h.cleanup();
}

/**
 * Realtime snapshots (REST) — observe sensor changes by polling.
 *
 * What you'll build: a live dashboard's data path using only fetch — write a
 * sensor reading, then observe it and a new matching sensor via repeated GET /
 * query requests.
 * Real-world scenario: the SDK exposes native WebSocket onSnapshot; a fetch-only
 * client has no WebSocket, so this example uses the outbox/REST polling path and
 * labels it explicitly. The committed mutation is always asserted.
 */
import { harness, check } from "./_harness.mjs";

const h = await harness("realtime-snapshot");
const col = h.prefix;
const docPath = `${col}/sensor-1`;
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function pollUntil(predicate, timeoutMs = 6000) {
  const deadline = Date.now() + timeoutMs;
  while (Date.now() < deadline) {
    if (await predicate()) return true;
    await sleep(100);
  }
  return false;
}

try {
  h.log("=== Realtime Snapshots ===");
  const seeded = await h.api.data("POST", `/documents/${docPath}`, { data: { reading: 1, channel: "sensors" } });
  check(seeded.status === 201, "seed sensor");

  const mode = "REST polling (fetch-only; no WebSocket transport)";

  // --- Document observation --------------------------------------------------
  const patched = await h.api.data("PATCH", `/documents/${docPath}`, { data: { reading: 2 } });
  check(patched.ok, "writing the new reading succeeded");
  const observedDoc = await pollUntil(async () => {
    const snap = await h.api.data("GET", `/documents/${docPath}`);
    return snap.ok && snap.body.data.reading === 2;
  });
  check(observedDoc, "REST GET eventually observed the committed reading");
  h.log({ transport: mode, target: "document", initialCallback: false, readingViaRest: 2, mutationAsserted: true });

  // --- Query observation -----------------------------------------------------
  const createdSecond = await h.api.data("POST", `/documents/${col}/sensor-2`, {
    data: { reading: 3, channel: "sensors" },
  });
  check(createdSecond.status === 201, "second matching sensor created");
  let count = 0;
  const observedQuery = await pollUntil(async () => {
    const result = await h.api.data("POST", "/query", {
      collectionPath: col,
      where: [{ field: "channel", op: "==", value: "sensors" }],
      orderBy: [],
      limit: 50,
      select: null,
      startAt: null,
      startAfter: null,
    });
    count = result.body.documents?.length ?? 0;
    return count === 2;
  });
  check(observedQuery, "REST query eventually returned both matching sensors");
  h.log({ transport: mode, target: "query", initialCallback: false, countViaRest: count, mutationAsserted: true });

  const final = await h.api.data("GET", `/documents/${docPath}`);
  check(final.body.data.reading === 2, "final sensor reading is committed");
  h.log({ finalReading: final.body.data.reading });
} finally {
  await h.cleanup();
}
