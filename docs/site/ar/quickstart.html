البداية / البدء السريع

البدء السريع#

يُدخلك هذا الدليل في عالم VELLUM خلال دقائق قليلة: كتابة مستند وقراءته مجددًا. نستخدم SDK الرسمي بلغة TypeScript/JavaScript وهو @vellumdb/sdk-js.

السيناريو#

لقد أنشأت مشروعًا جديدًا وتريد التأكد من أن الإعداد يعمل من طرف إلى طرف: ثبّت SDK، وأنشئ عميلًا بمفتاح إنتاج، واكتب مستند مستخدم واحدًا، واقرأه مجددًا، ثم احذفه. في نهاية هذا الدليل سيكون لديك عميل عامل يمكنك توسيعه ل بقية ميزات SDK. المشروع هو المستأجر الوحيد.

1. ثبّت SDK#

BASH
npm install @vellumdb/sdk-js

الحزمة هي ESM (type: module) وتستهدف Node 22+ أو متصفحًا حديثًا. وتتضمن تعريفات TypeScript الخاصة بها، لذا لا حاجة إلى حزمة @types منفصلة.

2. احصل على مفتاح مشروع#

يجب على طلب مستوى المستندات تقديم مفتاح API في الترويسة x-project-key. أنشئ مفتاحًا ضمن بيئة مشروعك. عامل مفاتيح الخادم (sk_) كأسرار؛ يمكن شحن المفاتيح العامة (pk_) إلى المتصفحات وتطبيقات الجوال لكنها لا تمنح أي وصول ضمني — تُفحص كل عملية مقابل قواعد أمان البيئة.

لا تلتزم بمفتاح حقيقي في التحكم بالمصادر. استخدم عنصرًا نائبًا مثل <YOUR_API_KEY> في الأمثلة، وحمّل القيمة الحقيقية من متغير بيئة وقت التشغيل.

3. أنشئ عميلًا#

TS
import { createClient } from "@vellumdb/sdk-js";

const db = createClient({
  endpoint: process.env.VELLUM_ENDPOINT ?? "http://localhost:8080",
  projectId: process.env.VELLUM_PROJECT_ID ?? "proj_01JCK9X2P8", // اختياري؛ الافتراضي production (الأسماء القديمة مقبولة)
  apiKey: process.env.VELLUM_API_KEY ?? "<YOUR_API_KEY>",
  // اختياري: قدّم JWT للمستخدم النهائي حتى تتمكن القواعد من تقييم auth.uid / auth.claims.
  getAuthToken: async () => currentUserJwt(),
});

يتطلب createClient كلًا من projectId وapiKey. تكون endpoint افتراضيًا http://localhost:8080. يمكن لتحديد realtimeUrl اختياريًا تجاوز عنوان WebSocket المشتق <endpoint>/v1/realtime، أما customFetch / webSocketFactory فهما نقاط اختبار (test seams). تُرسل جميع الطلبات إلى /v1/projects/:projectId/....

4. اكتب واقرأ واحذف#

TS
const users = db.collection("users");
const user = users.doc("user_123");

await user.create({ name: "Ada", role: "admin", active: true });
const snapshot = await user.get();
console.log(snapshot.id, snapshot.version, snapshot.data());

await user.update({ active: false });
await user.delete();
  • يفشل create إذا كان المستند موجودًا بالفعل (ALREADY_EXISTS).
  • يدمج set(data, { merge: true }) بعمق؛ وبدون merge يستبدل المستند.
  • يعدّل update الحقول المحددة ويمكن أن يحمل تحويلات حقول ذرية.
  • يكتب delete علامة حذف (tombstone) وحدثًا في صندوق البريد؛ إنه حذف ناعم.

بمجرد وجود مستند، يمكنك الاستعلام عن المجموعة مباشرة:

TS
// اقرأ جميع المستخدمين النشطين، عشرة في كل مرة.
const active = await users.where("active", "==", true).limit(10).get();
for (const doc of active.docs) console.log(doc.id, doc.data());

راجع CRUD لقواعد المسارات وتحويلات الحقول لـ fieldOp.*.

إعداد البيئة#

يقرأ خادم API التهيئة من متغيرات البيئة (ومن ملف .env اختياري). المفيدة للتطوير المحلي:

المتغيرالمعنىالافتراضي
DATABASE_MODEmemory للاختبارات المعزولة، postgres للتخزين الدائمmemory
CONTROL_DATABASE_URLاتصال PostgreSQL بمستوى التحكمpostgres://vellum:vellum_dev_password@localhost:5432/control_db
DATA_DATABASE_URLاتصال PostgreSQL بمستوى البياناتpostgres://vellum:vellum_dev_password@localhost:5433/data_db
DATA_DATABASE_URL_LISTENعنوان وضع الجلسة المحجوز لعميل LISTEN الخاص بالوقت الفعليغير محدد (وقت فعلي بالاستطلاع فقط)
API_PORT / API_HOSTعنوان الاستماع8080 / 0.0.0.0
CURSOR_HMAC_SECRETيوقّع مؤشرات الترقيم الصفحيالافتراضي للتطوير (يجب استبداله في الإنتاج)
WARNING

في NODE_ENV=production يرفض الخادم التشغيل إذا كان أي سر تطوير مخبوء لا يزال مستخدمًا. اضبط قيمًا قوية وفريدة لـ BETTER_AUTH_SECRET وAPI_KEY_PEPPER وCURSOR_HMAC_SECRET وJWT_SECRET قبل النشر. لا تسجّل أبدًا عناوين الاتصال أو قيم الأسرار.

أمثلة موثّقة#

الأمثلة القابلة للتشغيل التالية تظهر كمصدر ثابت مرفق بمخرجات مسجّلة من المولّد.

المجموعة / البروتوكول
DART
import 'dart:io';
// Executed against the live PostgreSQL API by scripts/run-dart-examples.mjs.
//
// Quickstart — verify the connection and run one document lifecycle with
// `vellum_flutter`.
// What you'll build: a status-page service record that counts views.
// Real-world scenario: before building a screen, confirm the client can create,
// read, patch and delete a document. A short-lived server key is injected via
// `--dart-define=VELLUM_API_KEY=...`; no secret is hard-coded here.
import 'package:vellum_flutter/vellum_flutter.dart';

Future<void> main() async {
  final endpoint = Platform.environment['VELLUM_API_BASE'] ??
      const String.fromEnvironment('VELLUM_API_BASE',
          defaultValue: 'http://127.0.0.1:8080');
  final projectId = Platform.environment['VELLUM_PROJECT_ID'] ??
      const String.fromEnvironment('VELLUM_PROJECT_ID');
  final apiKey = Platform.environment['VELLUM_API_KEY'] ??
      const String.fromEnvironment('VELLUM_API_KEY');

  final client = VellumClient(
    endpoint: endpoint,
    projectId: projectId,
    apiKey: apiKey,
  );

  final prefix =
      'ex_flutter_quickstart_${DateTime.now().microsecondsSinceEpoch}';
  final ref = client.collection(prefix).doc('status-page');

  try {
    print('=== Quickstart (Flutter) ===');

    await ref
        .set({'service': 'checkout-api', 'status': 'operational', 'views': 0});
    final created = await ref.get();
    print('created: exists=${created.exists} version=${created.version}');

    await ref.update({'views': 1});
    final updated = await ref.get();
    final data = updated.data() ?? const <String, dynamic>{};
    print('updated: version=${updated.version} views=${data['views']}');

    await ref.delete();
    print('deleted: true');
  } finally {
    try {
      await ref.delete();
    } catch (_) {
      // Best effort cleanup; the doc may already be gone.
    }
    client.dispose();
  }
}

/**
 * Quickstart — verify the local API and run one full document lifecycle.
 *
 * What you'll build: a tiny status-page service record that counts views.
 * Real-world scenario: before wiring up an app, confirm the API is alive and
 * that a single document can be created, read, patched and removed safely.
 * Every run uses a unique path prefix and cleans up after itself.
 */
import { harness, check } from "./_harness.js";

const h = await harness("quickstart");
const doc = h.sdk.collection(h.prefix).doc("status-page");

try {
  h.log("=== Quickstart ===");

  const live = await h.api.raw<{ status: string }>("GET", "/v1/health/live");
  const ready = await h.api.raw<{ ready: boolean }>("GET", "/v1/health/ready");
  check(live.ok && live.body.status === "alive", "live health probe");
  check(ready.ok && ready.body.ready === true, "ready health probe");
  h.log({ live: live.body.status, ready: ready.body.ready });

  await doc.set({ service: "checkout-api", status: "operational", views: 0 });
  const created = await doc.get();
  check(created.exists && created.version === 1, "service document created at version 1");
  h.log({
    id: created.id,
    version: created.version,
    data: created.data(),
  });

  await doc.update({ views: 1 });
  const updated = await doc.get();
  check(updated.version === 2, "view increment advanced the version");
  h.log({ viewsAfterUpdate: (updated.data() as { views: number }).views, version: updated.version });

  await doc.delete();
  h.log({ deleted: true });
} finally {
  await h.cleanup();
}

/**
 * Quickstart (REST) — verify the API and run one full document lifecycle
 * with nothing but fetch.
 *
 * What you'll build: the same status-page hit counter as the SDK quickstart.
 * Real-world scenario: confirm the API is alive and that a document can be
 * created, read, patched and deleted using plain HTTP + x-project-key.
 */
import { harness, check } from "./_harness.mjs";

const h = await harness("quickstart");
const docPath = `${h.prefix}/status-page`;

try {
  h.log("=== Quickstart ===");

  const live = await h.api.raw("GET", "/v1/health/live");
  const ready = await h.api.raw("GET", "/v1/health/ready");
  check(live.ok && live.body.status === "alive", "live health probe");
  check(ready.ok && ready.body.ready === true, "ready health probe");
  h.log({ live: live.body.status, ready: ready.body.ready });

  const created = await h.api.data("POST", `/documents/${docPath}`, {
    data: { service: "checkout-api", status: "operational", views: 0 },
  });
  check(created.status === 201, "POST created the service document");

  const got = await h.api.data("GET", `/documents/${docPath}`);
  check(got.ok && got.body.version === 1, "GET returned version 1");
  h.log({ id: got.body.documentId, version: got.body.version, data: got.body.data });

  const patched = await h.api.data("PATCH", `/documents/${docPath}`, { data: { views: 1 } });
  check(patched.ok && patched.body.version === 2, "PATCH advanced the version");
  const after = await h.api.data("GET", `/documents/${docPath}`);
  h.log({ viewsAfterUpdate: after.body.data.views, version: after.body.version });

  const removed = await h.api.data("DELETE", `/documents/${docPath}`);
  check(removed.ok, "DELETE succeeded");
  h.log({ deleted: true });
} finally {
  await h.cleanup();
}

الأخطاء الشائعة#

  • شحن مفتاح sk_ إلى المتصفح. مفاتيح الخادم تتجاوز القواعد حسب النطاق؛ احتفظ بها على بنية تحتية موثوقة.
  • حذف projectId / apiKey. يتطلب createClient كلًا منهما؛ الإغفال يفشل عند الإنشاء.
  • استخدم مشاريع منفصلة للعزل. البيانات مقيدة بالمشروع فقط؛ لا توجد بيئات.
  • توقّع أن create يستبدل المستند. استخدم set(...) لاستبدال مستند موجود.

ماذا تقرأ بعد ذلك#

  • المصادقة — مفاتيح API، ومصادقة الجلسة، وMFA، والتدوير.
  • CRUD — المسارات، والمراجع، والتزامن، وتنسيق الأسلاك الموسوم.
  • الاستعلام — المرشحات والترتيب والإسقاط.
  • الوقت الفعلي — لقطات حية للمستندات والاستعلامات.
