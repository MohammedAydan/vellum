الكتابات الدفعية والمعاملات#

يوفّر VELLUM طريقتين لتجميع الكتابات: batchWrite لمجموعة ذرية واحدة من التعديلات، وrunTransaction لمنطق القراءة ثم الكتابة مع تحكم متفائل في التزامن (OCC).

السيناريو#

أنت تُهيّئ مستأجرًا جديدًا بمجموعة ثابتة معروفة من المستندات — كتابات يجب أن تنجح كلها أو لا شيء — لذا تستخدم batchWrite. ثم، عند تنفيذ تحويل بين حسابين تعتمد فيه الأرصدة الجديدة على قيم قرأتها أولًا، تستخدم runTransaction لتجنب فقدان التحديث.

TS
const result = await db.batchWrite([
  { type: "create", path: "users/u_123", data: { name: "Ada", credits: 0 } },
  { type: "set", path: "users/u_123/stats", data: { logins: 0 }, merge: false },
  { type: "update", path: "counters/users", data: { total: fieldOp.increment(1) } },
  { type: "delete", path: "sessions/old_session" },
]);

batchWrite#

الحدود والدلالات:

القيدالقيمةالخطأ عند التجاوز
العمليات لكل دفعة100BATCH_SIZE_EXCEEDED (400)
الحمولة المتسلسلة5 MiBPAYLOAD_TOO_LARGE (413)
  • يجب أن تكون الدفعة غير فارغة؛ مصفوفة writes الفارغة تُثير INVALID_ARGUMENT.
  • تُنفَّذ كل التعديلات داخل معاملة قاعدة بيانات واحدة. أي فشل يُلغي الدفعة بأكملها — لا يوجد نجاح جزئي.
  • تُتحقق التعديلات بالترتيب. فشل شرط ifVersion / exists يُثير FAILED_PRECONDITION (412)؛ وحذف مستند غير موجود يُثير NOT_FOUND (404)؛ وإنشاء مستند موجود يُثير ALREADY_EXISTS (409).
  • الكتابات مرتين إلى المسار نفسه في دفعة واحدة تحافظ على دلالة القراءة بعد الكتابة عبر طبقة داخل الدفعة.
  • كل تعديل ناجح يكتب حدث صندوق بريد في المعاملة نفسها، لذا يرى المشتركون الفعليون رؤية متسقة.

تحتوي النتيجة على نتيجة لكل تعديل بنفس ترتيب الكتابات المدخلة.

TS
// مصفوفة النتيجة تُطابق الكتابات المدخلة حسب الفهرس.
for (const r of (result as { results: Array<{ path: string }> }).results) {
  console.log(r.path);
}
WARNING

الدفعة ذرية لكنها ليست دورة قراءة-تعديل-كتابة: لا يمكنك فحص القيمة الحالية لمستند في منتصف الدفعة. استخدم معاملة لذلك.

runTransaction (OCC)#

تسمح المعاملة بقراءة المستندات وحساب قيم جديدة وإتمامها — مع ضمان عدم قيام كاتب آخر بتغيير مجموعة قراءتك في الفترة الفاصلة.

TS
const { result, commit } = await db.runTransaction(
  async (tx) => {
    const from = await tx.get("accounts/a");
    const to = await tx.get("accounts/b");
    const amount = 50;
    tx.update("accounts/a", { balance: from.data().balance - amount });
    tx.update("accounts/b", { balance: to.data().balance + amount });
    return { moved: amount };
  },
  { maxAttempts: 5 }
);

كيف تعمل:

  1. POST .../transactions:begin يُصدر transactionToken موقّعًا ويبدأ صفًا في جدول transactions بمستوى البيانات.
  2. tx.get() يقرأ عبر الرمز؛ وتُسجَّل كل قراءة في مجموعة قراءات المعاملة مع الإصدار الملاحظ.
  3. يُرتب استدعاؤك الكتابات (create, set, update, delete) دون إرسالها بعد.
  4. POST .../transactions:commit يتحقق من صف المعاملة ويقفله وكل مستند في مجموعة القراءات بترتيب path ASC الحتمي باستخدام SELECT ... FOR UPDATE، ويقارن الإصدارات الملاحظة، ثم يطبّق كل الكتابات المُرتَّبة وأحداث صندوق البريد في معاملة PostgreSQL أصلية واحدة (BEGIN / COMMIT / ROLLBACK).

وبما أن حالة القفل تعيش في PostgreSQL، تتشارك عدة حالات من المحرك في حالة OCC — لا يوجد Map داخل العملية ولا خدمة قفل خارجية.

إعادة المحاولة والتعارضات#

إذا تغيّر مستند في مجموعة القراءات، يُرفض الإتمام بـ ABORTED_CONFLICT (409). يلتقط runTransaction هذا الخطأ تحديدًا ويعيد تشغيل الاستدعاء كاملًا مع تراجع أُسّي قصير (25–500 ms)، حتى maxAttempts (الافتراضي 5). أي خطأ آخر يُثار فورًا.

TIP

أبقِ استدعاءات المعاملة صغيرة وخالية من التأثيرات الجانبية (لا استدعاءات شبكة، ولا إرسال رسائل بريد). قد يُشغَّل الاستدعاء أكثر من مرة عند حدوث تعارض.

المهلة#

يجب أن تكتمل المعاملات خلال 5 ثوانٍ (MAX_TRANSACTION_DURATION_MS). تجاوزها يُنتج TRANSACTION_TIMEOUT (408). العمل طويل الأمد لا مكان له في معاملة تفاعلية — احسب النتائج مسبقًا خارجها وأبقِ المعاملة قصيرة.

الحدالقيمةالخطأ
مدة المعاملة5,000 msTRANSACTION_TIMEOUT (408)
تعارض عند الإتمام—ABORTED_CONFLICT (409)، تُعاد محاولتها بواسطة SDK

الاختيار بينهما#

  • استخدم batchWrite عندما تعرف كل الكتابات مسبقًا ولا تعتمد على القيم الحالية.
  • استخدم runTransaction عندما تعتمد القيم الجديدة على مستندات قرأتها (عدّادات، أرصدة، فحوص تفرد).
  • استخدم ifVersion على كتابات CRUD الفردية عندما يكفي شرط مسبق لمستند واحد.

الأخطاء الشائعة#

  • القراءة في منتصف الدفعة. لا يمكن لـ batchWrite فحص القيم الحالية؛ استخدم معاملة عندما تعتمد الكتابات على القراءات.
  • تأثيرات جانبية داخل استدعاء المعاملة. قد يُشغَّل الاستدعاء عدة مرات عند التعارض؛ أبقِه نقيًا وخالًا من التأثيرات.
  • عمل طويل داخل معاملة. الميزانية 5 ثوانٍ تُنتج TRANSACTION_TIMEOUT؛ احسب مسبقًا خارجها.
  • تجاوز حدود الدفعة. أكثر من 100 عملية أو 5 MiB يُلغي الدفعة بأكملها دون نجاح جزئي.

import 'dart:io';
// Executed against the live PostgreSQL API by scripts/run-dart-examples.mjs.
//
// Batch write — onboard two users atomically.
// What you'll build: one batch that creates two users, patches one and deletes a
// stale user; a second batch with a stale ifVersion fails the whole request.
// Real-world scenario: provisioning a profile and settings row together so a
// partial signup can never be observed. `vellum_flutter` has no `batchWrite`
// helper, so `client.request('POST', '/batchWrite', body: ...)` is used.
import 'package:vellum_flutter/vellum_flutter.dart';

Future<void> main() async {
  final endpoint = Platform.environment['VELLUM_API_BASE'] ??
      const String.fromEnvironment('VELLUM_API_BASE',
          defaultValue: 'http://127.0.0.1:8080');
  final projectId = Platform.environment['VELLUM_PROJECT_ID'] ??
      const String.fromEnvironment('VELLUM_PROJECT_ID');
  final apiKey = Platform.environment['VELLUM_API_KEY'] ??
      const String.fromEnvironment('VELLUM_API_KEY');

  final client =
      VellumClient(endpoint: endpoint, projectId: projectId, apiKey: apiKey);
  final prefix =
      'ex_flutter_batch_write_${DateTime.now().microsecondsSinceEpoch}';
  final docPath = (String id) => '$prefix/$id';

  try {
    print('=== Batch Write (Flutter) ===');
    await client.request('POST', '/documents/${docPath('stale-user')}', body: {
      'data': {'seats': 0}
    });

    final result = await client.request('POST', '/batchWrite', body: {
      'writes': [
        {
          'type': 'create',
          'path': docPath('u1'),
          'data': {'seats': 1, 'group': 'onboarding'}
        },
        {
          'type': 'set',
          'path': docPath('u2'),
          'data': {'seats': 2, 'group': 'onboarding'}
        },
        {
          'type': 'update',
          'path': docPath('u1'),
          'data': {'seats': 10}
        },
        {'type': 'delete', 'path': docPath('stale-user')},
      ],
    });
    print('batch responseKeys=${result.keys.toList()}');

    final u1 = await client.doc(docPath('u1')).get();
    final u2 = await client.doc(docPath('u2')).get();
    print('u1 seats=${u1.data()?['seats']} u2 seats=${u2.data()?['seats']}');

    try {
      await client.request('POST', '/batchWrite', body: {
        'writes': [
          {
            'type': 'update',
            'path': docPath('u1'),
            'data': {'seats': 999},
            'ifVersion': 1
          },
          {
            'type': 'create',
            'path': docPath('should-not-exist'),
            'data': {'seats': 0}
          },
        ],
      });
    } on VellumException catch (e) {
      print('preconditionBatchCode=${e.code} status=${e.statusCode}');
    }
  } finally {
    for (final id in ['u1', 'u2', 'stale-user', 'should-not-exist']) {
      try {
        await client.doc(docPath(id)).delete();
      } catch (_) {}
    }
    client.dispose();
  }
}

/**
 * Batch write — onboard two users in one atomic request.
 *
 * What you'll build: a single batch that creates two user records, patches one
 * of them, and deletes a stale record — all or nothing.
 * Real-world scenario: a signup flow provisions a profile and a settings row
 * together. A second batch carries a stale ifVersion precondition; the whole
 * batch fails and a "should-not-exist" doc is never partially committed.
 */
import { harness, check } from "./_harness.js";

const h = await harness("batch-write");
const col = h.prefix;
const docPath = (id: string): string => `${col}/${id}`;

function errorCode(error: unknown): string {
  return (error as { code?: string }).code ?? "UNKNOWN";
}

try {
  h.log("=== Batch Write ===");
  // A delete mutation must target an existing document.
  await h.sdk.collection(col).doc("stale-user").set({ seats: 0 });

  const result = await h.sdk.batchWrite([
    { type: "create", path: docPath("u1"), data: { seats: 1, group: "onboarding" } },
    { type: "set", path: docPath("u2"), data: { seats: 2, group: "onboarding" } },
    { type: "update", path: docPath("u1"), data: { seats: 10 } },
    { type: "delete", path: docPath("stale-user") },
  ]);
  h.log({
    batchStatus: "ok",
    writesSubmitted: 4,
    responseKeys: Object.keys(result as object),
  });

  const u1 = await h.sdk.collection(col).doc("u1").get();
  const u2 = await h.sdk.collection(col).doc("u2").get();
  const removed = await h.api.data("GET", `/documents/${col}/stale-user`);
  check((u1.data() as { seats: number }).seats === 10, "create then update in one batch applied");
  check((u2.data() as { seats: number }).seats === 2, "set in batch applied");
  check(removed.status === 404, "delete in batch applied");
  h.log({
    u1: u1.data(),
    u2: u2.data(),
    deletedStatus: removed.status,
  });

  try {
    await h.sdk.batchWrite([
      { type: "update", path: docPath("u1"), data: { seats: 999 }, ifVersion: 1 },
      { type: "create", path: docPath("should-not-exist"), data: { seats: 0 } },
    ]);
    throw new Error("batch with stale precondition should have failed");
  } catch (error: unknown) {
    check(errorCode(error) === "FAILED_PRECONDITION", "stale batch returns FAILED_PRECONDITION");
    h.log({ preconditionBatchCode: errorCode(error) });
  }
  const rolledBack = await h.api.data("GET", `/documents/${col}/should-not-exist`);
  check(rolledBack.status === 404, "failed batch did not partially commit");
  h.log({ atomicRollback: rolledBack.status === 404 });
} finally {
  await h.cleanup();
}

import 'dart:io';
// Executed against the live PostgreSQL API by scripts/run-dart-examples.mjs.
//
// OCC transactions — transfer funds between two accounts atomically.
// What you'll build: a debit + credit staged in one `runTransaction`, plus a
// forced conflict and a stale-version precondition.
// Real-world scenario: a payments service reads both balances and commits both
// writes together; a competing write before commit aborts the transaction.
// Note: Dart's `runTransaction` returns the callback result directly (unlike
// the JS SDK, which returns `{ result, commit }`).
import 'package:vellum_flutter/vellum_flutter.dart';

Future<void> main() async {
  final endpoint = Platform.environment['VELLUM_API_BASE'] ??
      const String.fromEnvironment('VELLUM_API_BASE',
          defaultValue: 'http://127.0.0.1:8080');
  final projectId = Platform.environment['VELLUM_PROJECT_ID'] ??
      const String.fromEnvironment('VELLUM_PROJECT_ID');
  final apiKey = Platform.environment['VELLUM_API_KEY'] ??
      const String.fromEnvironment('VELLUM_API_KEY');

  final client =
      VellumClient(endpoint: endpoint, projectId: projectId, apiKey: apiKey);
  final prefix =
      'ex_flutter_transactions_${DateTime.now().microsecondsSinceEpoch}';
  final col = client.collection(prefix);
  final fromRef = col.doc('account-a');
  final toRef = col.doc('account-b');

  try {
    print('=== OCC Transactions (Flutter) ===');
    await fromRef.set({'owner': 'ada', 'balance': 100});
    await toRef.set({'owner': 'ben', 'balance': 50});

    final transfer = await client.runTransaction((tx) async {
      final from = await tx.get(fromRef);
      final to = await tx.get(toRef);
      final fromBefore = (from.data()?['balance'] as num).toInt();
      final toBefore = (to.data()?['balance'] as num).toInt();
      const amount = 50;
      final fromAfter = fromBefore - amount;
      final toAfter = toBefore + amount;
      tx.update(fromRef, {'balance': fromAfter});
      tx.update(toRef, {'balance': toAfter});
      return {
        'amount': amount,
        'fromBefore': fromBefore,
        'toBefore': toBefore,
        'fromAfter': fromAfter,
        'toAfter': toAfter
      };
    });
    print('transfer=$transfer');

    final finalFrom = await fromRef.get();
    final finalTo = await toRef.get();
    print(
        'fromBalance=${finalFrom.data()?['balance']} toBalance=${finalTo.data()?['balance']}');

    // Forced conflict: change a read doc before committing a held transaction.
    final begin = await client.request('POST', '/transactions:begin', body: {});
    final token = begin['transactionToken'] as String;
    final held = await client.request(
      'GET',
      '/documents/${fromRef.path}?transactionToken=${Uri.encodeQueryComponent(token)}',
    );
    final heldVersion = held['version'];
    await fromRef.update({'balance': 51});
    try {
      await client.request('POST', '/transactions:commit', body: {
        'transactionToken': token,
        'writes': [
          {
            'type': 'update',
            'path': fromRef.path,
            'data': {'balance': 200},
            'ifVersion': heldVersion
          },
        ],
      });
    } on VellumException catch (e) {
      print('forced conflict: code=${e.code} status=${e.statusCode}');
    }

    try {
      await fromRef.update({'balance': 300}, ifVersion: 1);
    } on VellumException catch (e) {
      print('stale precondition: code=${e.code} status=${e.statusCode}');
    }
  } finally {
    for (final ref in [fromRef, toRef]) {
      try {
        await ref.delete();
      } catch (_) {}
    }
    client.dispose();
  }
}

/**
 * OCC transactions — transfer funds between two accounts atomically.
 *
 * What you'll build: a balance transfer that debits one account and credits
 * another inside a single interactive OCC transaction.
 * Real-world scenario: a payments service reads both balances, stages the two
 * writes, and commits them together. A competing write that changes a read
 * balance before commit forces ABORTED_CONFLICT (409); a stale plain update
 * yields FAILED_PRECONDITION (412). The two are reported with distinct labels.
 */
import { harness, check } from "./_harness.js";

const h = await harness("transactions");
const col = h.prefix;
const fromPath = `${col}/account-a`;
const toPath = `${col}/account-b`;

try {
  h.log("=== OCC Transactions ===");

  await h.sdk.collection(col).doc("account-a").set({ owner: "ada", balance: 100 });
  await h.sdk.collection(col).doc("account-b").set({ owner: "ben", balance: 50 });

    const to = await t.get<{ owner: string; balance: number }>(toPath);
    const fromBefore = from.data().balance;
    const toBefore = to.data().balance;
    const amount = 50;
    t.update(fromPath, { balance: fromBefore - amount });
    t.update(toPath, { balance: toBefore + amount });
    return { amount, fromBefore, toBefore, fromAfter: fromBefore - amount, toAfter: toBefore + amount };
  });

    toBalance: (toFinal.data() as { balance: number }).balance,
    version: fromFinal.version,

  const token = begin.body.transactionToken;
  check(Boolean(token), "transaction token was issued");

    transactionToken: token,
    writes: [{ type: "update", path: fromPath, data: { balance: 200 }, ifVersion: heldVersion }],
  });
  check(conflict.status === 409, "forced conflict returns HTTP 409");
  const conflictCode = (conflict.body as { error?: { code?: string } })?.error?.code;
  check(conflictCode === "ABORTED_CONFLICT", "forced conflict code is ABORTED_CONFLICT");
  h.log({ scenario: "forced write/write conflict", status: conflict.status, code: conflictCode });

  // Deliberate stale-version precondition on an ordinary update.
  try {
    await h.sdk.collection(col).doc("account-a").update({ balance: 300 }, { ifVersion: 1 });
    throw new Error("stale update should have failed");
  } catch (error: unknown) {
    const code = (error as { code?: string }).code;
    check(code === "FAILED_PRECONDITION", "stale ifVersion code is FAILED_PRECONDITION");
    h.log({ scenario: "stale-version precondition", code, status: (error as { status?: number }).status });
  }
} finally {
  await h.cleanup();
}

/**
 * OCC transactions (REST) — transfer funds between two accounts atomically.
 *
 * What you'll build: a balance transfer staged inside /transactions:begin and
 * committed with /transactions:commit, plus a forced write/write conflict and a
 * stale-version precondition.
 * Real-world scenario: a payments service debits one account and credits
 * another in one transaction; a competing write before commit aborts it.
 */
import { harness, check } from "./_harness.mjs";

const h = await harness("transactions");
const col = h.prefix;
const fromPath = `${col}/account-a`;
const toPath = `${col}/account-b`;

try {
  h.log("=== OCC Transactions ===");
  check((await h.api.data("POST", `/documents/${fromPath}`, { data: { owner: "ada", balance: 100 } })).status === 201, "seed sender");
  check((await h.api.data("POST", `/documents/${toPath}`, { data: { owner: "ben", balance: 50 } })).status === 201, "seed receiver");

  // --- Happy path: read both balances, stage two writes, commit together. ----
  const begin = await h.api.data("POST", "/transactions:begin", {});
  const token = begin.body.transactionToken;
  check(Boolean(token), "transaction token issued");
  const from = await h.api.data("GET", `/documents/${fromPath}?transactionToken=${encodeURIComponent(token)}`);
  const to = await h.api.data("GET", `/documents/${toPath}?transactionToken=${encodeURIComponent(token)}`);
  const fromBefore = from.body.data.balance;
  const toBefore = to.body.data.balance;
  const amount = 50;
  const transfer = { amount, fromBefore, toBefore, fromAfter: fromBefore - amount, toAfter: toBefore + amount };
  const commit = await h.api.data("POST", "/transactions:commit", {
    transactionToken: token,
    writes: [
      { type: "update", path: fromPath, data: { balance: transfer.fromAfter } },
      { type: "update", path: toPath, data: { balance: transfer.toAfter } },
    ],
  });
  check(commit.ok, "transaction committed");
  h.log({ commit: "ok", transfer, commitResponseKeys: Object.keys(commit.body) });

  const fromFinal = await h.api.data("GET", `/documents/${fromPath}`);
  const toFinal = await h.api.data("GET", `/documents/${toPath}`);
  check(fromFinal.body.data.balance === 50, "sender debited");
  check(toFinal.body.data.balance === 100, "receiver credited");
  h.log({
    fromBalance: fromFinal.body.data.balance,
    toBalance: toFinal.body.data.balance,
    version: fromFinal.body.version,
  });

  // --- Forced conflict: mutate a read doc before commit. --------------------
  const begin2 = await h.api.data("POST", "/transactions:begin", {});
  const token2 = begin2.body.transactionToken;
  const held = await h.api.data("GET", `/documents/${fromPath}?transactionToken=${encodeURIComponent(token2)}`);
  const heldVersion = held.body.version;
  const outside = await h.api.data("PATCH", `/documents/${fromPath}`, { data: { balance: 51 } });
  check(outside.ok, "outside write applied");
  const conflict = await h.api.data("POST", "/transactions:commit", {
    transactionToken: token2,
    writes: [{ type: "update", path: fromPath, data: { balance: 200 }, ifVersion: heldVersion }],
  });
  check(conflict.status === 409, "forced conflict returns HTTP 409");
  check(conflict.body?.error?.code === "ABORTED_CONFLICT", "conflict code is ABORTED_CONFLICT");
  h.log({ scenario: "forced write/write conflict", status: conflict.status, code: conflict.body.error.code });

  // --- Stale-version precondition on an ordinary PATCH. ---------------------
  const stale = await h.api.data("PATCH", `/documents/${fromPath}`, { data: { balance: 300 }, ifVersion: 1 });
  check(stale.status === 412 && stale.body?.error?.code === "FAILED_PRECONDITION", "stale patch rejected");
  h.log({ scenario: "stale-version precondition", code: stale.body.error.code, status: stale.status });
} finally {
  await h.cleanup();
}
