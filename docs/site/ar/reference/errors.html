الرموز المعيارية للأخطاء وإرشادات إعادة المحاولة#

جميع الأخطاء تستخدم مغلّفًا واحدًا. يُنتج VellumError.toEnvelope(requestId) وبرمجية أخطاء HTTP (apps/api/src/middleware/error-handler.ts) ما يلي:

JSON
{
  "error": {
    "code": "FAILED_PRECONDITION",
    "message": "Version conflict on users/u_123",
    "requestId": "req_...",
    "details": { "path": "users/u_123" }
  }
}

details اختياري (يُحذف عند كونه فارغًا). ويعكس requestId قيمة X-Request-Id (أو req_unknown). المصدر المعتمد: packages/core/src/errors.ts (ERROR_HTTP_STATUS، VellumError) وpackages/api-contract/src/schemas/errors.ts (ErrorCodeEnum) والقسم 4 من AGENTS.md.

رموز موجودة في ErrorCodeEnum دون خريطة حالة في النواة#

يُعلن مخطط Zod ErrorCodeEnum (في api-contract) أيضًا عن ABORTED وRESOURCE_EXHAUSTED وDEADLINE_EXCEEDED وUNAVAILABLE وINTERNAL. هذه ليست مفاتيح في ERROR_HTTP_STATUS في @vellum/core ولا يمكن إنشاء VellumError بها. إذا وصل أحدها إلى برمجية أخطاء HTTP فإنه يسقط في الفرع ?? 500 (الحالة 500)؛ أما الخطأ العام غير المُعالَج فيُسلسَل كـ code:"INTERNAL" بالحالة 500. فضّل المكافئات المُخرَطة أعلاه (ABORTED_CONFLICT، RATE_LIMITED/QUOTA_EXCEEDED، QUERY_DEADLINE_EXCEEDED، SERVICE_UNAVAILABLE، INTERNAL_ERROR) في الكود الجديد.

NOTE

INTERNAL مقابل INTERNAL_ERROR

كلاهما قد يظهر على الإرسال بالحالة 500. وINTERNAL_ERROR هو الرمز المعياري لـ VellumError (له خرطة 500 صريحة)؛ أمّا INTERNAL فهو رمز المغلّف الاحتياطي للاستثناءات غير المتوقعة. عامل الاثنين كـ"عطل في الخادم، أعد المحاولة بقتار وأدرج requestId في أي بلاغ."

سياسة إعادة المحاولة بنظرة سريعة#

آمن إعادة المحاولة (مع تراجع)أعد المحاولة فقط بعد تغيير شيء مالا تُعد المحاولة أبدًا بشكل أعمى
TRANSACTION_TIMEOUT، ABORTED_CONFLICT، RATE_LIMITED، SERVICE_UNAVAILABLE، QUERY_DEADLINE_EXCEEDED، INTERNAL_ERROR (مرة)UNAUTHENTICATED (جدّد الرمز)، FAILED_PRECONDITION (أعد قراءة الحالة)، QUOTA_EXCEEDED (انتظر إعادة الضبط)أخطاء 4xx للتحقق/التصريح: INVALID_ARGUMENT، INVALID_DOCUMENT_PATH، INVALID_FIELD_NAME، MAX_NESTING_EXCEEDED، BATCH_SIZE_EXCEEDED، INVALID_CURSOR، QUERY_TOO_COMPLEX، LIMIT_EXCEEDED، PERMISSION_DENIED، NOT_FOUND، ALREADY_EXISTS، DOCUMENT_TOO_LARGE، PAYLOAD_TOO_LARGE، RESPONSE_TOO_LARGE، SLOW_CONSUMER_DISCONNECT

التراجع ذو التشتيت الكامل (full-jitter) الذي تستخدمه مجموعتا SDK لإعادة الاتصال ولإعادة محاولة OCC: sleep = random(0, min(tMax, t0 · 2^attempt)) مع t0 = 500 ms وtMax = 30,000 ms (computeReconnectBackoffMs). وتستخدم إعادة محاولة إيداع OCC في JS SDK القيم t0 = 25 ms وtMax = 500 ms.
