الاستعلام#

تُجرى الاستعلامات مقابل collectionPath واحد داخل نطاق (projectId). يبني SDK مواصفات الاستعلام ويرسلها إلى /v1/projects/:projectId/query.

TS
const page = await db
  .collection("users")
  .where("age", ">=", 18)
  .where("status", "==", "active")
  .orderBy("age", "desc")
  .select("name", "age")
  .limit(25)
  .get();

السيناريو#

أنت تبني شاشة إدارة تعرض العملاء المشتركين، مرتبين من الأحدث، وتُظهر اسمهم وخطتهم فقط. تجمع بين مرشح مساواة ومرشح نطاق وترتيب على حقل مخصص، وهو ما يتطلب فهرسًا مركّبًا — ويخبرك الخادم تمامًا بالفهرس المطلوب إن كان غائبًا.

TS
const customers = await db
  .collection("users")
  .where("plan", "==", "pro")
  .where("createdAt", ">=", "2026-01-01T00:00:00.000Z")
  .orderBy("createdAt", "desc")
  .select("name", "plan")
  .limit(50)
  .get();

عوامل التصفية#

العاملنوع القيمةالدلالة
==قيمة مفردة، طابع زمني، مرجع، nullمساواة تامة مكتوبة.
!=قيمة مفردة، طابع زمني، مرجع، nullالحقل موجود وغير مساوٍ.
<, <=, >, >=رقم، int64، نص، طابع زمنيمقارنة نطاق مكتوبة داخل العائلة نفسها.
inمصفوفة من 1–30 قيمةالحقل يساوي أي عنصر.
not-inمصفوفة من 1–30 قيمةالحقل موجود ولا يساوي أي عنصر.
array-containsعددى، طابع زمني، مرجعحقل المصفوفة يحتوي القيمة.
array-contains-anyمصفوفة من 1–30 قيمةحقل المصفوفة يحتوي قيمة واحدة على الأقل.

تعمل أسماء حقول خاصة في المرشحات والترتيب: documentId (أو __name__) لمعرّف المستند، وcreatedAt / updatedAt للطوابع الزمنية التي يديرها الخادم.

الترتيب والإسقاط والحدود#

  • حتى 10 جمل where و3 جمل orderBy. تجاوزها يُثير QUERY_TOO_COMPLEX.
  • يُلحق document_id ASC تلقائيًا كفاصل حسم نهائي، لذا تعود المستندات المتساوية في قيم الترتيب دائمًا بترتيب ثابت.
  • يُسقط select(...fields) الحقول المحددة فقط من المستوى الأعلى. بدونه تُعاد خريطة data كاملة.
  • يقبل limit(n) القيم 1–500 وافتراضه 50. القيمة الأكبر من 500 تُثير LIMIT_EXCEEDED.
  • يمكن للمصفوفات الانفصالية (in, not-in, array-contains-any) أن تحمل 30 عنصرًا كحد أقصى.
  • استجابة الاستعلام الأكبر من 4 MiB تُثير RESPONSE_TOO_LARGE.
  • تنفيذ الاستعلام محدد بـ 5 ثوانٍ؛ تجاوزها يُنتج QUERY_DEADLINE_EXCEEDED.

أداة بناء الاستعلام غير قابلة للتعديل: تُرجع where وorderBy وlimit وselect وstartAt وstartAfter أداة جديدة، لذا يمكنك إعادة استخدام استعلام أساسي بأمان.

TS
// استعلام أساسي قابل لإعادة الاستخدام؛ كل استدعاء يشتق أداة جديدة.
const base = db.collection("users").where("active", "==", true);
const young = await base.where("age", "<", 30).get();
const seniors = await base.where("age", ">=", 65).get();

تُعرّف toQuerySpec() الكائن العادي الذي يُرسل على مستوى الأسلاك.

المؤشرات (cursors)#

استخدم startAt(cursor) لتضمين صف الحد أو startAfter(cursor) لاستبعاده، مع تمرير nextCursor من صفحة سابقة:

TS
const first = await db.collection("users").orderBy("age").limit(50).get();
if (first.nextCursor) {
  const second = await db
    .collection("users")
    .orderBy("age")
    .limit(50)
    .startAfter(first.nextCursor)
    .get();
}

المؤشرات موقّعة بـ HMAC ومرتبطة بالشكل الدقيق للاستعلام. إعادة استخدام أحدها بمرشحات أو ترتيب مختلف يُثير INVALID_CURSOR. راجع الترقيم الصفحي.

متى يُطلب فهرس مركّب#

تستخدم مرشحات المساواة البسيطة الفهارس المدمجة ولا تتطلب إعدادًا. أما الاستعلام الذي يجمع مرشحات نطاق أو حقول ترتيب مخصصة متعددة فيتطلب فهرسًا مركّبًا مطابقًا. إن لم يوجد، يُرجع الخادم FAILED_PRECONDITION (412) مع suggestedIndex في تفاصيل الخطأ:

JSON
{
  "error": {
    "code": "FAILED_PRECONDITION",
    "message": "Query on 'users' requires a composite index for the requested filters and sort order.",
    "details": {
      "collectionPath": "users",
      "suggestedIndex": { "collectionPath": "users", "fields": [{ "path": "status", "dir": "asc" }] }
    }
  }
}
TIP

أنشئ الفهرس المقترح عبر واجهة الفهارس، ثم أعد المحاولة بعد أن تكون حالته ready. راجع الفهارس المركّبة.

ملاحظات تجميع SQL#

يُجمّع محرك الاستعلام استعلامًا مُتحققًا منه ومُطبَّعًا إلى SQL مُعلَّم (parameterized) — دون سلسلة قيم مستخدم مُلصقة. يحدث التجميع والتنفيذ داخل الحزم، وليس في معالجات المسارات مطلقًا:

  1. الفهارس المدمجة صفرية الإعداد تغطي (project_id, collection_path, document_id) وupdated_at وcreated_at، إضافةً إلى فهرس GIN على data jsonb_path_ops لمعاملات الاحتواء (==, in, array-contains).
  2. الفهارس المركّبة تُحل من صفوف document_indexes؛ وتوجد الإدخالات المطابقة في document_index_entries بمفتاح sort_key BYTEA يحافظ على الترتيب، مما يتيح مسح نطاق B-tree واحدًا.
  3. سياق المستأجر مُربوط عبر SET LOCAL في المعاملة، لذا تُصفّي سياسات RLS في PostgreSQL كل صف.
  4. مسح الاحتياط غير المفهرس محدد بسقف أمان؛ ولا يُقتطع من النتائج بصمت. غياب فهرس مركّب مطلوب هو خطأ صريح، لا مسح بطيء.

يُسقط SDK الحقل documents إلى QuerySnapshot.docs (مع مُوصّل data())، وينسخ nextCursor وmeta إلى اللقطة.

NOTE

الحقل compiledSql في meta هو أداة تصحيح أخطاء. يحتوي على الجملة المجمّعة مع المعلمات مرتبطة بشكل منفصل؛ لا تعامله كعقد يمكن تحليله.

الأخطاء الشائعة#

  • تجاوز حدود الجمل. أكثر من 10 جمل where أو 3 حقول orderBy أو حد يتجاوز 500 يُثير QUERY_TOO_COMPLEX / LIMIT_EXCEEDED.
  • خلط أنواع القيم في النطاق. تقارن < و<= و> و>= داخل العائلة نفسها؛ مقارنة نص برقم لن تُطابق كما تتوقع.
  • إعادة استخدام مؤشر مع استعلام مختلف. المؤشر مرتبط بالمرشحات والترتيب والمشروع والبيئة؛ تغيير أي منها يُنتج INVALID_CURSOR.
  • الاعتماد على compiledSql. إنه حقل تصحيح أخطاء، وليس عقد API مستقرًا.

مثال موثّق#

المجموعة / البروتوكول
DART
import 'dart:io';
// Executed against the live PostgreSQL API by scripts/run-dart-examples.mjs.
//
// Structured queries — analytics filters over revenue events.
// What you'll build: a ranked "top events in a region" view plus a disjunctive
// `in` filter, using the immutable query builder.
// Real-world scenario: the widget needs only a few fields and an exact set of
// revenue bands. Note: `vellum_flutter`'s Query has no `select()` builder method;
// use `toQuerySpec()` with `client.request('POST', '/query', body: spec)` when
// field projection is required.
import 'package:vellum_flutter/vellum_flutter.dart';

Future<void> main() async {
  final endpoint = Platform.environment['VELLUM_API_BASE'] ??
      const String.fromEnvironment('VELLUM_API_BASE',
          defaultValue: 'http://127.0.0.1:8080');
  final projectId = Platform.environment['VELLUM_PROJECT_ID'] ??
      const String.fromEnvironment('VELLUM_PROJECT_ID');
  final apiKey = Platform.environment['VELLUM_API_KEY'] ??
      const String.fromEnvironment('VELLUM_API_KEY');

  final client =
      VellumClient(endpoint: endpoint, projectId: projectId, apiKey: apiKey);
  final prefix = 'ex_flutter_query_${DateTime.now().microsecondsSinceEpoch}';
  final col = client.collection(prefix);

  try {
    print('=== Structured Queries (Flutter) ===');
    for (final fixture in [
      {'id': 'a', 'event': 'signup', 'region': 'north', 'revenue': 10},
      {'id': 'b', 'event': 'purchase', 'region': 'south', 'revenue': 20},
      {'id': 'c', 'event': 'renewal', 'region': 'north', 'revenue': 30},
      {'id': 'd', 'event': 'upgrade', 'region': 'south', 'revenue': 40},
      {'id': 'e', 'event': 'purchase', 'region': 'north', 'revenue': 50},
    ]) {
      await col.doc(fixture['id'] as String).set(fixture);
    }

    final topNorth = await col
        .where('region', '==', 'north')
        .orderBy('revenue', dir: 'desc')
        .limit(3)
        .get();
    print('top north ids=${topNorth.docs.map((d) => d.id).toList()}');
    for (final doc in topNorth.docs) {
      print('  ${doc.id}: ${doc.data()}');
    }

    final bands =
        await col.where('revenue', 'in', [10, 40]).orderBy('revenue').get();
    print('in filter ids=${bands.docs.map((d) => d.id).toList()}');

    final spec = col.where('region', '==', 'south').limit(1).toQuerySpec();
    print('toQuerySpec: $spec');
  } finally {
    // Best effort cleanup of the seeded fixtures.
    for (final id in ['a', 'b', 'c', 'd', 'e']) {
      try {
        await col.doc(id).delete();
      } catch (_) {}
    }
    client.dispose();
  }
}

/**
 * Structured queries — build immutable query steps with where/orderBy/limit/
 * select and execute them through the SDK.
 *
 * What you'll build: an analytics view over revenue events, filtered by region
 * and ranked by revenue.
 * Real-world scenario: a dashboard asks for "top 3 events in the north region"
 * and for an exact set of revenue bands via a disjunctive `in` filter. `select`
 * keeps the response small by projecting only the columns the chart needs.
 */
import { harness, check } from "./_harness.js";

const h = await harness("query");
const col = h.prefix;

const fixtures: Array<{ id: string; event: string; region: string; revenue: number }> = [
  { id: "a", event: "signup", region: "north", revenue: 10 },
  { id: "b", event: "purchase", region: "south", revenue: 20 },
  { id: "c", event: "renewal", region: "north", revenue: 30 },
  { id: "d", event: "upgrade", region: "south", revenue: 40 },
  { id: "e", event: "purchase", region: "north", revenue: 50 },
];

try {
  h.log("=== Structured Queries ===");
  for (const fixture of fixtures) {
    await h.sdk.collection(col).doc(fixture.id).set(fixture);
  }

  const topNorth = await h.sdk
    .collection(col)
    .where("region", "==", "north")
    .orderBy("revenue", "desc")
    .limit(3)
    .select("event", "revenue")
    .get();
  check(topNorth.docs.length === 3, "expected three north-region events");
  check(topNorth.docs[0]?.id === "e", "highest revenue first");
  h.log({
    query: "region == north ORDER BY revenue DESC LIMIT 3 SELECT event,revenue",
    ids: topNorth.docs.map((doc) => doc.id),
    rows: topNorth.docs.map((doc) => doc.data()),
  });

  const inQuery = await h.sdk
    .collection(col)
    .where("revenue", "in", [10, 40])
    .orderBy("revenue", "asc")
    .get();
  check(inQuery.docs.length === 2, "in filter matched exactly two revenue bands");
  h.log({
    query: "revenue in [10,40] ORDER BY revenue ASC",
    ids: inQuery.docs.map((doc) => doc.id),
    indexUsed: (inQuery.meta as { indexUsed?: string } | null)?.indexUsed,
  });

  const spec = h.sdk.collection(col).where("region", "==", "south").limit(1).toQuerySpec();
  h.log({
    query: "toQuerySpec() (no network call)",
    where: spec.where,
    orderBy: spec.orderBy,
    limit: spec.limit,
  });
} finally {
  await h.cleanup();
}

/**
 * Structured queries (REST) — analytics filters over the /query endpoint.
 *
 * What you'll build: a ranked "top events in a region" view plus a disjunctive
 * `in` filter, using the raw query request body.
 * Real-world scenario: a dashboard needs only a few projected fields and an
 * exact set of revenue bands, so it posts a structured spec instead of
 * scanning the whole collection.
 */
import { harness, check } from "./_harness.mjs";

const h = await harness("query");
const col = h.prefix;
const fixtures = [
  { id: "a", event: "signup", region: "north", revenue: 10 },
  { id: "b", event: "purchase", region: "south", revenue: 20 },
  { id: "c", event: "renewal", region: "north", revenue: 30 },
  { id: "d", event: "upgrade", region: "south", revenue: 40 },
  { id: "e", event: "purchase", region: "north", revenue: 50 },
];

try {
  h.log("=== Structured Queries ===");
  for (const fixture of fixtures) {
    const res = await h.api.data("POST", `/documents/${col}/${fixture.id}`, { data: fixture });
    check(res.status === 201, `seed fixture ${fixture.id}`);
  }

  const topNorth = await h.api.data("POST", "/query", {
    collectionPath: col,
    where: [{ field: "region", op: "==", value: "north" }],
    orderBy: [{ field: "revenue", dir: "desc" }],
    limit: 3,
    select: ["event", "revenue"],
    startAt: null,
    startAfter: null,
  });
  check(topNorth.ok && topNorth.body.documents.length === 3, "three north-region events");
  const topIds = topNorth.body.documents.map((d) => d.documentId);
  check(topIds[0] === "e", "highest revenue first");
  h.log({
    query: "region == north ORDER BY revenue DESC LIMIT 3 SELECT event,revenue",
    ids: topIds,
    rows: topNorth.body.documents.map((d) => d.data),
  });

  const inQuery = await h.api.data("POST", "/query", {
    collectionPath: col,
    where: [{ field: "revenue", op: "in", value: [10, 40] }],
    orderBy: [{ field: "revenue", dir: "asc" }],
    limit: 50,
    select: null,
    startAt: null,
    startAfter: null,
  });
  const inIds = inQuery.body.documents.map((d) => d.documentId);
  check(inQuery.ok && inIds.length === 2, "in filter matched two bands");
  h.log({
    query: "revenue in [10,40] ORDER BY revenue ASC",
    ids: inIds,
    indexUsed: inQuery.body.meta?.indexUsed,
  });

  h.log({
    query: "raw query spec (no execution)",
    spec: { collectionPath: col, where: [{ field: "region", op: "==", value: "south" }], limit: 1 },
  });
} finally {
  await h.cleanup();
}
