Operations / Live Verification

Live Verification#

Both SDK testbeds run against a live VELLUM API backed by real PostgreSQL control/data planes. No mocks, simulations or skips were used. All numbers below are taken verbatim from the evidence file.

Commands and results#

BASH
# JS / TypeScript testbed (CLI + dashboard share one scenario implementation)
corepack pnpm --filter @vellum/js-testbed-app run verify:live
# → 12/12 PASS, exit 0 — run twice in the same API process

# Flutter / Dart CLI testbed
cd examples/flutter_testbed_app
PATH="/home/ubuntu/projects/document-db/.tools/dart-sdk/bin:$PATH" \
  VELLUM_API_BASE_URL=http://127.0.0.1:8080 dart run bin/run_live_testbed.dart
# → 12/12 PASS, exit 0
PATH="/home/ubuntu/projects/document-db/.tools/dart-sdk/bin:$PATH" dart test
# → PASS (1/1 live E2E wrapper, 12 scenarios, ~16 s)

# Flutter SDK gates
cd sdks/flutter && dart analyze --fatal-infos --fatal-warnings && dart test
# → "No issues found!" · 48 tests PASS

Each app provisions its own isolated organization, project, pk_/sk_ keys, ruleset and auth config with per-run unique slugs/emails, then cleans up. Only status and latency are printed; tokens, keys and DB URLs are redacted.
