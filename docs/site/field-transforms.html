Core concepts / Field Transforms

Field Transforms#

Field transforms let the server compute a field value atomically, avoiding a read-modify-write race. The SDK exposes five helpers under fieldOp; on the wire each becomes a sentinel object with a $op key.

TS
import { fieldOp } from "@vellumdb/sdk-js";

Scenario#

Several users can "like" a post at the same time, and you want an accurate likeCount without coordinating clients. You use increment(1) to bump the counter atomically and arrayUnion to record unique reactor ids — the server applies both in one transaction, so no update is lost.

The five operations#

SDK helperWire sentinelBehavior
fieldOp.serverTimestamp(){ "$op": "serverTimestamp" }Replaced with the transaction's UTC timestamp as { "$t": "ts", "$v": "...", "$ms": ... }.
fieldOp.increment(n = 1){ "$op": "inc", "by": n }Adds n to the current value. Missing field initializes to n.
fieldOp.arrayUnion(...items){ "$op": "arrayUnion", "elements": [...] }Appends items not already present (typed deep equality).
fieldOp.arrayRemove(...items){ "$op": "arrayRemove", "elements": [...] }Removes every occurrence matching any item.
fieldOp.deleteField(){ "$op": "deleteField" }Removes the field from its parent map.
TS
await db.collection("users").doc("u_123").set(
  {
    loginCount: fieldOp.increment(1),
    roles: fieldOp.arrayUnion(["developer", "architect"]),
    tags: fieldOp.arrayRemove(["trial"]),
    lastLoginAt: fieldOp.serverTimestamp(),
    legacyFlag: fieldOp.deleteField(),
  },
  { merge: true }
);

arrayUnion and arrayRemove accept either variadic arguments or a single array argument (fieldOp.arrayUnion(["a", "b"]) and fieldOp.arrayUnion("a", "b") are equivalent).

On the wire the increment operation also accepts the alias $op: "increment" with $v / value; the canonical SDK helper emits inc with by.

TS
// Two independent counters updated in a single write.
await db.collection("stats").doc("global").update({
  posts: fieldOp.increment(1),
  lastPostAt: fieldOp.serverTimestamp(),
});

Where transforms are allowed#

Transforms are accepted in write paths where the engine validates data with field operations enabled:

  • DocumentReference.set with { merge: true }
  • DocumentReference.update (HTTP PATCH)
  • batchWrite mutations
  • transaction commits (tx.set / tx.update)

They are not valid in create payloads or in query values. A sentinel appearing where transforms are not allowed raises INVALID_ARGUMENT.

Atomicity and ordering#

  • All transforms in a single write are applied inside the same database transaction, using one shared transaction timestamp for serverTimestamp.
  • The patch is walked in object-key insertion order. Nested plain objects are merged recursively, so a transform can sit at any depth.
  • arrayUnion and arrayRemove use wire-value equality, so tagged values (timestamps, references, int64) compare correctly rather than by JavaScript identity.
  • For increment, if the current value is a tagged int64 ($t: "int"), the server computes in BigInt and stores a tagged int64 result; otherwise it uses IEEE-754 addition.
NOTE

Because transforms are evaluated server-side at commit time, two clients incrementing the same counter concurrently do not lose updates. If you also need preconditions across several documents, use a transaction.

Restrictions and failure modes#

  • Incrementing a field whose current value is not numeric (and not a tagged int64) throws FAILED_PRECONDITION (412).
  • A field named __proto__, constructor, or prototype is rejected at every merge level with INVALID_FIELD_NAME to prevent prototype-pollution gadgets.
  • inc requires a finite numeric by value; arrayUnion / arrayRemove require an elements array.
  • An unknown $op value throws INVALID_ARGUMENT.
  • Transformed values still go through the normal wire-format validation: 20-level nesting cap, 256-character field names, and 1 MiB document size.
WARNING

Do not mix a transform with a precondition that depends on the same field's post-transform value. ifVersion compares the document version before the write; it does not validate the transformed result.

Common pitfalls#

  • Using a transform in create or a query value. Those paths reject $op sentinels with INVALID_ARGUMENT.
  • Incrementing a non-numeric field. The first write must initialize the field to a number (or a tagged int64).
  • Assuming read-your-writes inside a transform. Transforms are computed at commit time against the current stored value.
  • Using ifVersion to protect a transformed field. The precondition checks the pre-write version, not the computed result.

Verified example#

SDK / protocol
DART
import 'dart:io';
// Executed against the live PostgreSQL API by scripts/run-dart-examples.mjs.
//
// Atomic field transforms — update engagement counters without lost updates.
// What you'll build: a social post whose likes, tags and history change via
// `$op` sentinels, with a field removed and a server timestamp added.
// Real-world scenario: concurrent readers like and tag a post; sending field
// operations (not a client-side read/modify/write) keeps the counter correct.
import 'package:vellum_flutter/vellum_flutter.dart';

Future<void> main() async {
  final endpoint = Platform.environment['VELLUM_API_BASE'] ??
      const String.fromEnvironment('VELLUM_API_BASE',
          defaultValue: 'http://127.0.0.1:8080');
  final projectId = Platform.environment['VELLUM_PROJECT_ID'] ??
      const String.fromEnvironment('VELLUM_PROJECT_ID');
  final apiKey = Platform.environment['VELLUM_API_KEY'] ??
      const String.fromEnvironment('VELLUM_API_KEY');

  final client =
      VellumClient(endpoint: endpoint, projectId: projectId, apiKey: apiKey);
  final prefix =
      'ex_flutter_field_transforms_${DateTime.now().microsecondsSinceEpoch}';
  final ref = client.collection(prefix).doc('social-post');

  try {
    print('=== Atomic Field Transforms (Flutter) ===');

    await ref.set({
      'likes': 10,
      'tags': ['launch'],
      'history': ['featured'],
      'scratch': 'temporary'
    });
    print('before: ${(await ref.get()).data()}');

    await ref.update({
      'likes': FieldOp.increment(5),
      'tags': FieldOp.arrayUnion(['release', 'news']),
      'history': FieldOp.arrayRemove(['featured']),
      'updatedAt': FieldOp.serverTimestamp(),
      'scratch': FieldOp.deleteField(),
    });

    final data = (await ref.get()).data() ?? const <String, dynamic>{};
    final stamp = data['updatedAt'];
    print('likes=${data['likes']} tags=${data['tags']}');
    print(
        'scratchAbsent=${!data.containsKey('scratch')} updatedAtWire=${stamp is Map ? stamp['\$t'] : null}');
  } finally {
    try {
      await ref.delete();
    } catch (_) {
      // Best effort cleanup.
    }
    client.dispose();
  }
}

/**
 * Atomic field transforms — apply engagement updates in one server-side PATCH.
 *
 * What you'll build: a social post whose likes, tags, moderation history and
 * last-modified stamp are updated atomically, with a scratch field removed.
 * Real-world scenario: two readers "like" and tag a post at the same time.
 * Sending $op sentinels (instead of client-side read/modify/write) avoids lost
 * updates. The serverTimestamp value is logged by its wire type, never its clock.
 */
import { fieldOp } from "../../packages/sdk-js/src/index.js";
import { harness, check } from "./_harness.js";

const h = await harness("field-transforms");
const ref = h.sdk.collection(h.prefix).doc("social-post");

try {
  h.log("=== Atomic Field Transforms ===");

  await ref.set({ likes: 10, tags: ["launch"], history: ["featured"], scratch: "temporary" });
  const before = await ref.get();
  h.log({ before: before.data() });

  await ref.update({
    likes: fieldOp.increment(5),
    tags: fieldOp.arrayUnion("release", "news"),
    history: fieldOp.arrayRemove("featured"),
    updatedAt: fieldOp.serverTimestamp(),
    scratch: fieldOp.deleteField(),
  });

  const after = (await ref.get()).data() as Record<string, unknown>;
  check(after.likes === 15, "increment applied");
  check(Array.isArray(after.tags) && after.tags.length === 3, "arrayUnion appended two tags");
  check(!("scratch" in after), "deleteField removed the scratch key");
  const stamp = after.updatedAt as { $t?: string };
  check(stamp?.$t === "ts", "serverTimestamp uses the tagged ts wire type");
  h.log({
    likes: after.likes,
    tags: after.tags,
    removedFieldAbsent: !("scratch" in after),
    serverTimestampWireType: stamp.$t,
  });
} finally {
  await h.cleanup();
}

/**
 * Atomic field transforms (REST) — apply engagement updates in one PATCH.
 *
 * What you'll build: a social post whose likes, tags and moderation history
 * change via $op sentinels, with one field removed and a server stamp added.
 * Real-world scenario: concurrent readers update a counter without a
 * client-side read/modify/write race. The timestamp is logged by wire type.
 */
import { harness, check } from "./_harness.mjs";

const h = await harness("field-transforms");
const docPath = `${h.prefix}/social-post`;

try {
  h.log("=== Atomic Field Transforms ===");

  const seeded = await h.api.data("POST", `/documents/${docPath}`, {
    data: { likes: 10, tags: ["launch"], history: ["featured"], scratch: "temporary" },
  });
  check(seeded.status === 201, "seed post");
  const before = await h.api.data("GET", `/documents/${docPath}`);
  h.log({ before: before.body.data });

  const patched = await h.api.data("PATCH", `/documents/${docPath}`, {
    data: {
      likes: { $op: "inc", by: 5 },
      tags: { $op: "arrayUnion", elements: ["release", "news"] },
      history: { $op: "arrayRemove", elements: ["featured"] },
      updatedAt: { $op: "serverTimestamp" },
      scratch: { $op: "deleteField" },
    },
  });
  check(patched.ok, "transform patch applied");

  const after = (await h.api.data("GET", `/documents/${docPath}`)).body.data;
  check(after.likes === 15, "increment applied");
  check(Array.isArray(after.tags) && after.tags.length === 3, "arrayUnion appended two tags");
  check(!("scratch" in after), "deleteField removed the scratch key");
  check(after.updatedAt?.$t === "ts", "serverTimestamp uses the ts wire type");
  h.log({
    likes: after.likes,
    tags: after.tags,
    removedFieldAbsent: !("scratch" in after),
    serverTimestampWireType: after.updatedAt.$t,
  });
} finally {
  await h.cleanup();
}
