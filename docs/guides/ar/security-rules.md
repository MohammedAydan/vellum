# قواعد الأمان

تقرر قواعد الأمان ما إذا كان مفتاح API عام (`pk_`) قد يقرأ مستندًا أو يكتبه. تُخزَّن كـ **شجرة تركيب مجرّدة (AST)** بصيغة JSON مُرجَّلة في مستوى التحكم، وتُقيَّم بشكل متزامن داخل الذاكرة — دون توليد كود أو تنفيذه أبدًا.

:::note
مفاتيح الخادم (`sk_`) تتجاوز شجرة القواعد للعمليات التي تغطيها نطاقاتها. أما المفاتيح العامة فتُقيَّم القواعد دائمًا؛ ومع غياب مجموعة قواعد نشطة يُرفض الوصول.
:::

## السيناريو

تدير تطبيقًا متعدد المستخدمين حيث يمكن لكل مستخدم قراءة مستند `users/{userId}` الخاص به وكتابته فقط، بينما يمكن لمجموعة إدارة صغيرة قراءة كل المستخدمين. تنشر مجموعة قواعد تربط الملكية بمقطع المسار، وتتحقق منها في محاكي القواعد (Rule Simulator)، وتتأكد من أن طلب `pk_` غير المصرّح به يحصل على `PERMISSION_DENIED`.

## شكل مجموعة القواعد (v1)

```json
{
  "version": 1,
  "rules": [
    {
      "match": "users/{userId}",
      "allow": {
        "get": { "op": "==", "left": { "var": "auth.uid" }, "right": { "var": "path.userId" } },
        "list": { "op": "==", "left": { "var": "auth.claims.role" }, "right": { "val": "admin" } },
        "create": {
          "op": "all",
          "conditions": [
            { "op": "==", "left": { "var": "auth.uid" }, "right": { "var": "path.userId" } },
            { "op": "==", "left": { "var": "request.data.ownerId" }, "right": { "var": "auth.uid" } }
          ]
        },
        "update": { "op": "==", "left": { "var": "resource.data.ownerId" }, "right": { "var": "auth.uid" } },
        "delete": { "op": "==", "left": { "var": "auth.claims.role" }, "right": { "val": "admin" } }
      }
    }
  ]
}
```

يجب أن يكون `version` هو `1` وأن تكون `rules` مصفوفة. لكل قاعدة نمط مسار `match` وكائن `allow` مفاتيحه هي العمليات: `get` و`list` و`create` و`update` و`delete`، إضافةً إلى الاختصارين `read` (يغطي `get`/`list`) و`write` (يغطي `create`/`update`/`delete`).

### مطابقة البدل (wildcard)

- `{paramName}` يربط مقطعًا واحدًا بـ `path.<paramName>`.
- `{document=**}` في نهاية النمط يطابق مقطعًا واحدًا أو أكثر من المقاطع المتبقية ويربط المسار الفرعي النسبي بـ `path.document`.
- إذا طابقت قواعد متعددة مسارًا، يُمنح الوصول عندما تُقيَّم **أي** قاعدة مطابقة بـ true للعملية (دلالات OR القياسية). عدم وجود تطابق، أو عدم وجود تعبير صحيح، يعني الرفض.

## عوامل التعبير

| الفئة | العوامل |
| :--- | :--- |
| المقارنات | `==`, `!=`, `<`, `<=`, `>`, `>=`, `in` |
| الكائن/النوع | `hasKey`, `isType` |
| الدوال المركّبة | `all` (كل `conditions`)، `any` (بعض `conditions`)، `not` (شرط واحد `condition`) |

المعاملات إما `{ "val": ... }` للقيمة الحرفية أو `{ "var": "..." }` لقيمة من السياق:

| المتغير | المعنى |
| :--- | :--- |
| `auth.uid` | معرّف المستخدم النهائي من رمز Bearer JWT (null بدون رمز). |
| `auth.claims.<path>` | مطالبة (claim) من JWT الخاص بالمستخدم النهائي. |
| `path.<param>` | القيمة التي يربطها بدل في `match`. |
| `resource.data[.<path>]` | بيانات المستند الحالية (null عند الإنشاء). |
| `request.data[.<path>]` | بيانات المستند الواردة (null عند القراءة أو الحذف). |
| `request.time` | طابع زمني للطلب بالمللي ثانية من الحقبة (epoch). |

تستخدم كل المقارنات مساواة وترتيب قيم الأسلاك المكتوبة نفسهما اللذين يستخدمهما محرك الاستعلام.

## التقييم الحتمي والحدود

- التقييم متزامن بالكامل وداخل الذاكرة: لا تنفيذ كود ديناميكي، ولا استدعاءات شبكة، ولا إدخال/إخراج متكرر. لا يمكن للتعبيرات المعقدة تحويل الطلب إلى متجه لحرمان الخدمة.
- يفرض التحقق **عمق AST أقصى 10** و**100 عقدة كحد أقصى لكل تعبير قاعدة**. تجاوز أي منهما يُثير `QUERY_TOO_COMPLEX`.
- تُرفض المراجع الدائرية وقت التحقق، وتُقيَّم العوامل أو المعاملات غير المعروفة بـ false (رفض).
- **الرفض الافتراضي:** يُثير `authorizeOperation` الخطأ `PERMISSION_DENIED` (403) إلا إذا سمحت قاعدة مطابقة بالعملية صراحةً.

:::warning
تُتحقق القواعد مقابل مخطط v1 وقت النشر. أي AST مشوّه (إصدار خاطئ، أو غياب `match`/`allow`، أو عملية/عامل غير مدعوم) يُرفض بـ `INVALID_ARGUMENT` قبل أن يصير نشطًا.
:::

## النشر والمحاكاة

انشر عبر Console API المصادق عليه بالجلسة:

| الطريقة | نقطة النهاية | الغرض |
| :--- | :--- | :--- |
| `POST` | `/v1/projects/:projectId/rulesets` | التحقق من إصدار جديد ونشره؛ يكتب سجل تدقيق ويُبطل المخابئ. |
| `GET` | `/v1/projects/:projectId/rulesets` | قراءة مجموعة القواعد النشطة (أو الافتراضي المدمج عند عدم نشر أي مجموعة). |

```bash
curl -X POST "https://api.example.com/v1/projects/<PROJECT_ID>/rulesets" \
  -H "Authorization: Bearer <SESSION_TOKEN>" \
  -H "content-type: application/json" \
  -d '{ "rulesAst": { "version": 1, "rules": [ /* ... */ ] } }'
```

يؤثر النشر فورًا على المشروع: تُبطل مجموعة القواعد محليًا وعبر الحالات بواسطة `NOTIFY vellum_cache_invalidate`. ولإجراء تجربة جافة قبل النشر، يُقيّم **محاكي القواعد** في لوحة التحكم AST مرشحًا مقابل سياق مصادقة ومسار محاكى ويُبلغ عما إذا كان الطلب سيُسمح وأي قاعدة طابقته.

## أنماط أقل قدر من الامتيازات

```json
{
  "match": "users/{userId}/orders/{orderId}",
  "allow": {
    "get": { "op": "==", "left": { "var": "auth.uid" }, "right": { "var": "path.userId" } },
    "create": {
      "op": "all",
      "conditions": [
        { "op": "==", "left": { "var": "auth.uid" }, "right": { "var": "path.userId" } },
        { "op": "isType", "left": { "var": "request.data.total" }, "right": { "val": "number" } }
      ]
    }
  }
}
```

اربط معرّف المالك بمقطع مسار بدلًا من الوثوق بحقل يقدّمه العميل، وتحقق من `resource.data` عند التعديل حتى لا يمكن نقل الملكية عبر تصحيح خبيث.

## الأخطاء الشائعة

- **الوثوق بحقل مالك يقدّمه العميل.** اربط الملكية بمقطع مسار وتحقق منها مقابل `auth.uid`.
- **السماح بالتعديل دون فحص `resource.data`.** قد ينقل تصحيح خبيث الملكية إذا تحققت من البيانات الواردة فقط.
- **نسيان الرفض الافتراضي.** إذا لم تطابق أي قاعدة يُرفض الوصول — انشر مجموعة القواعد وتأكد من الشكل (`version: 1`).
- **مجموعات قواعد عميقة أو كبيرة جدًا.** تجاوز العمق 10 أو 100 عقدة لكل تعبير يُثير `QUERY_TOO_COMPLEX` وقت النشر.
