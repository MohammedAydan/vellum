# قواعد الأمان

تحدد القواعد صلاحيات عمليات المستندات التي تستخدم مفتاح مشروع عامًا. يحدد المفتاح العام المشروع، ولا يثبت هوية المستخدم. تأتي الهوية من رمز مستخدم نهائي تم التحقق منه. عدم وجود قواعد نشطة، أو مسار مطابق، أو تعبير ناجح يعني PERMISSION_DENIED. تستخدم مفاتيح الخادم نطاقاتها الصريحة بدل قواعد المستخدمين. لا تضع مفتاح خادم داخل تطبيق العميل.

## البداية: مساحة خاصة بكل مستخدم

ضع البيانات الخاصة تحت users/{userId}/notes/{noteId}. قارن هوية المستخدم بمتغير المسار، وليس بحقل ملكية يرسله العميل. بهذه البنية يمكن السماح بالاستعلام على مجموعة المستخدم دون الحاجة لقراءة بيانات مستند أثناء فحص list.

```json
{
  "version": 1,
  "rules": [
    {
      "match": "users/{userId}/notes/{noteId}",
      "allow": {
        "get": { "op": "all", "conditions": [
          { "op": "!=", "left": { "var": "auth.uid" }, "right": { "val": null } },
          { "op": "==", "left": { "var": "auth.uid" }, "right": { "var": "path.userId" } }
        ] },
        "list": { "op": "all", "conditions": [
          { "op": "!=", "left": { "var": "auth.uid" }, "right": { "val": null } },
          { "op": "==", "left": { "var": "auth.uid" }, "right": { "var": "path.userId" } }
        ] },
        "create": { "op": "all", "conditions": [
          { "op": "==", "left": { "var": "auth.uid" }, "right": { "var": "path.userId" } },
          { "op": "isType", "left": { "var": "request.data.title" }, "right": { "val": "string" } }
        ] },
        "update": { "op": "all", "conditions": [
          { "op": "==", "left": { "var": "auth.uid" }, "right": { "var": "path.userId" } },
          { "op": "isType", "left": { "var": "request.data.title" }, "right": { "val": "string" } }
        ] },
        "delete": { "op": "==", "left": { "var": "auth.uid" }, "right": { "var": "path.userId" } }
      }
    }
  ]
}
```

المتغيرات الملتقطة من المسار نصوص. لذلك لا يمكن أن تساوي هوية null متغير userId النصي في عمليات الكتابة أعلاه. يشرح [دليل DSL](./security-rules-dsl.md) الصيغة المقروءة وأمثلة إضافية.

## مطابقة المسارات واختيار العملية

تحتوي القواعد على version:1 ومصفوفة rules. لكل قاعدة match وallow. استخدم مسارات JSON النسبية مثل users/{userId} دون بادئة المشروع. يلتقط {userId} جزءًا واحدًا في path.userId. ضع {rest=**} في نهاية النمط؛ يلتقط جزءًا واحدًا أو أكثر. قاعدة مستند الأب لا تمنح صلاحيات تلقائية للمجموعات الفرعية. تتحول كتل match المتداخلة في DSL إلى قواعد مستقلة دون وراثة للصلاحيات.

| العملية | السياق |
| --- | --- |
| get | قراءة مستند واحد، مع بياناته الحالية إن كان موجودًا. |
| list | بوابة استعلام مجموعة أو تجميع أو اشتراك أو قراءة دفعية؛ راجع الاختلافات أدناه. |
| create | إنشاء مستند، بما في ذلك set عندما لا يوجد مستند. |
| update | تعديل جزئي أو دمج أو استبدال مستند موجود. |
| delete | حذف مستند موجود. |
| read | بديل احتياطي في JSON لعمليتي get وlist. |
| write | بديل احتياطي في JSON لعمليات create وupdate وdelete. |

تأخذ العملية الصريحة الأولوية على البديل في JSON حتى إن كانت false: وجود get:false وread:true يمنع get داخل القاعدة نفسها. أما القواعد المستقلة المطابقة فتعمل بمنطق OR؛ يكفي نجاح واحدة للسماح، ولا توجد قاعدة منع تتغلب على السماح. يوسع DSL الاختصارين read وwrite إلى عمليات مستقلة. تكرار عملية داخل كتلة match نفسها يستبدل تعبيرها السابق؛ ادمج شروطها في تصريح واحد.

## مرجع متغيرات السياق

| متغير JSON | المعنى |
| --- | --- |
| auth.uid | معرّف المستخدم المتحقق منه، أو null دون هوية. افحص uid != null، وليس auth != null. |
| auth.email | البريد من الهوية المتحقق منها، أو null عند غيابه. |
| auth.email_verified | حالة التحقق من البريد، أو null عند غيابها. |
| auth.is_anonymous | حالة الحساب المجهول، أو null عند غيابها. قد يكون للحساب المجهول uid. |
| auth.claims.<field> | مطالبة متداخلة تم التحقق منها؛ تستخدم hasRole الحقل المفرد claims.role. |
| request.auth.* | مرادف auth.* في JSON وDSL. |
| path.<wildcard> | قيمة نصية التقطها match. فضّل path.userId الصريحة؛ يدعم المترجم المصحح أيضًا الاسم المنفرد المطابق لمتغير المسار. |
| resource.data | المستند المخزن؛ null عند الإنشاء أو عندما لا يتم تحميل المورد. |
| request.data | المستند الجديد الكامل بعد الدمج والتحويلات والتحقق، وليس جسم التعديل الجزئي. null عند القراءة والحذف. |
| request.time | وقت التقييم بالميلي ثانية منذ epoch، وليس كائن timestamp. |

في DSL تعني resource.title المسار resource.data.title. وتعني incoming.title وrequest.resource.data.title المسار request.data.title. هذه اختصارات للمترجم وليست جذور متغيرات جديدة في JSON. لا يتاح auth.token ولا request.query للقواعد.

الحقل الغائب يساوي undefined وليس null. تفشل المقارنة == وكذلك != إذا كان أحد الطرفين undefined. لذلك قد ينجح نفي مقارنة فاشلة؛ لا تستخدم !(incoming.missing == resource.missing) لإثبات وجود حقل. استخدم hasKey وisType. متغير المسار غير المرتبط يرجع null، لذا اشترط الهوية باستخدام isSignedIn أو isOwner عند مقارنة قيم اختيارية.

## جميع تعبيرات JSON

التعبير إما true أو false أو عقدة عامل. الطرف إما {val: literal} أو {var: contextPath}. تحتوي العوامل المنطقية تعبيرات، بينما تحتوي المقارنات أطرافًا؛ لا تنفذ عمليات حسابية أو استدعاءات دوال متداخلة أثناء التشغيل.

| العامل | البنية والسلوك |
| --- | --- |
| ==, != | left وright؛ مساواة wire ذات أنواع محددة دون تحويل تلقائي، ويجب أن يُحل الطرفان. |
| <, <=, >, >= | ترتيب wire الخاص بالاستعلامات. لا تجتاز null أو undefined المقارنة. افحص نوع الرقم أولًا. |
| in | يجب أن يساوي left عنصرًا في مصفوفة right. ليس بحث نص أو فحص مفتاح. |
| hasKey | left كائن غير مصفوفة، وright اسم مفتاح مباشر مملوك للكائن. للحقل المتداخل مرر كائن الأب. |
| isType | left القيمة، وright اسم نوع من الجدول التالي. |
| all | مصفوفة conditions غير فارغة؛ تنجح كل الشروط. |
| any | مصفوفة conditions غير فارغة؛ ينجح شرط واحد على الأقل. |
| not | نفي تعبير condition واحد. |

| اسم isType | القيمة المقبولة |
| --- | --- |
| null | null صريحة، لا الحقل الغائب. |
| bool, boolean | قيمة منطقية. |
| string | نص. |
| number | رقم JSON عادي؛ tagged int ليس number. |
| array | مصفوفة. |
| map | كائن غير null وغير مصفوفة، دون مفتاح $t مملوك له. |
| int, ts, ref, bytes, geo | قيمة wire موسومة بالنوع المطابق. افحص ref قبل قراءة $v. |

لا تستخدم الترتيب بين أنواع مختلفة كتحقق عددي. ليست hasKey قائمة بالحقول المسموحة. لا توجد دوال عامة للحجم أو regex أو diff أو length أو جلب مستند آخر أو exists أو البحث في قاعدة البيانات.

## الاستعلام ليس فحص get لكل مستند

يفحص الاستعلام العادي list مرة واحدة على مسار اصطناعي داخل المجموعة، ويكون resource.data وrequest.data كلاهما null. لا يفحص get لكل نتيجة ولا يضيف مرشحات ملكية. تستخدم التجميعات بوابة list نفسها. منح list على مجموعة بها ملاك مختلفون قد يكشف سجلات يرفض get قراءتها منفردة. مرشح where للمالك داخل عميل غير موثوق ليس حاجز أمان؛ يمكن حذفه من الطلب.

استخدم مجموعات خاصة تحت كل مستخدم وافحص path.userId لكل من get وlist. شرط list المبني على resource.data.ownerId يفشل في بوابة المجموعة حتى لو احتوى الاستعلام على مرشح للمالك. لا تقارن متغير معرّف المستند الأخير بـ uid أثناء list؛ إنه علامة اصطناعية لا معرّف سجل حقيقي.

تفحص القراءة الدفعية list لكل مجموعة ثم get مع بيانات كل مستند، وتحذف المستندات المرفوضة من النتائج. يفحص الحذف الجماعي list ثم delete لكل مستند مختار. يفحص البحث العكسي عن المراجع get للهدف وكلًا من get وlist للسجلات التي تشير إليه. لا تفترض تطابق فحوص جميع واجهات القراءة.

## الوقت الفعلي والعلاقات

يتطلب اشتراك استعلام list عند البداية على مسار اصطناعي. وتتطلب الصفوف والأحداث الفردية get مع بيانات المستند، بما في ذلك سلوك اللقطة الأولى المصحح. يجري اشتراك مستند مباشر أيضًا فحص get قبل تحميل البيانات؛ لذلك قد يفشل إعداد الاشتراك إذا اعتمد الشرط فقط على resource. تعمل ملكية المسار في المرحلتين. اختبر البداية والتغييرات وإعادة التشغيل منفصلة. لا يجعل فحص get في الوقت الفعلي استعلامات HTTP العادية أكثر تقييدًا.

المرجع بيانات، وليس منح صلاحية ولا استعلام قواعد عبر المستندات. تفحص الأهداف المضمنة get مستقلًا مع بيانات الهدف. تُحجب المراجع المرفوضة بدل كشفها عبر المصدر. لا تستطيع القاعدة التأكد من وجود الهدف أو قراءة مالكه. استخدم بنية مسارات موثوقة واختبر تضمين هدف خاص. قواعد سلامة العلاقات مختلفة عن قواعد الأمان.

حزمة storage محول لتخزين المستندات، وليست لغة قواعد مستقلة لمخازن ملفات العميل. لا تستخدم أنماط Firebase الخاصة بالملفات ولا تفترض حماية خدمة رفع ملفات أخرى بهذه القواعد.

## الحدود والأخطاء والاختبار الآمن

| الحد | القيمة |
| --- | --- |
| عدد القواعد | 200 |
| عمق التعبير | 10 |
| عقد التعبير | 100 لكل عملية بعد توسيع الدوال |
| طول نمط المسار | 2048 حرفًا |
| طول مسار المتغير | 512 حرفًا |
| مصفوفة الطرف الأيمن لـ in | 256 عنصرًا كحد أقصى، مع ميزانية خطوات التقييم |
| عمل التعبير وقت التشغيل | 256 خطوة؛ قد يستنفد بحث عضوية كبير الميزانية |

يرفض التحقق العوامل والبنى غير الصحيحة. قد يمر متغير غير معروف بالتحقق البنيوي لكنه يرجع undefined؛ النفي وOR يعنيان أن تعبيرًا فرعيًا خاطئًا لا يضمن رفض القاعدة كلها. تُحظر أجزاء الحقول المرتبطة بسلسلة prototype. خطأ التعقيد هو QUERY_TOO_COMPLEX، وخطأ البنية INVALID_ARGUMENT، ورفض الصلاحية PERMISSION_DENIED. المفتاح غير الصحيح أو المنتهي أو الملغى مشكلة مصادقة منفصلة.

حدد هوية الاختبار والعملية والمسار والبيانات القديمة والجديدة الكاملة. اختبر دون هوية، وبمستخدم آخر، وحقول غائبة وأنواع خاطئة وتغيير ملكية وحذف مرشحات العميل والمسارات المتداخلة والدفعات والتضمينات الخاصة واشتراكات الوقت الفعلي. استخدم مفتاحًا عامًا لأن مفتاح الخادم قد يتجاوز القواعد التي تختبرها.

واجهات التجميع والمحاكاة أدوات كتابة وليست تفعيلًا للقواعد ولا كتابة للمستندات. نجاح المحاكاة لا يثبت نجاح العملية الحقيقية لأن سياقها يُمرر مباشرة. لا يدعي هذا الدليل دعم تفعيل القواعد عبر أي SDK. تحقق من طلبات المستندات الحقيقية مع القواعد النشطة قبل الاعتماد على التغيير.
